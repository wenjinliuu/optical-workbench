# Optical Workbench · 视光业务工作台

根据[产品设计蓝图 V1.1](https://optical-workbench-blueprint.wenjinuu.chatgpt.site)启动的第一阶段基础开发版。V0.48 使用浅色、鲜明的蓝色主色，薄荷绿、紫色与珊瑚橙区分业务。当前可保存客户档案、周期草稿、家长授权与多周期到店，管理本店人员及账号安全、查看六个分阶段虚构场景，上传/下载/撤销客户附件，并保留资料修订版本，提供门店/岗位/家庭权限、审计及运行恢复工具。新增独立“配镜与商品”入口，维护商品目录并实际保存订单明细、固定原到店需求和资料版本，支持草稿修订、取消及历史。另接通商品数量/订单预留释放与分次收款登记、原单金额保护、误录历史和门店查询。独立“订货与加工”看板可安排原单实物行、分批到货/备料、开工/完成及交期，保留历史并保护原单和已备料库存。新增“质检与交付”，保存明确项目、不合格返工/重新质检及合格批次分项签收。新增“批次出库”“售后与追溯”，核对实际数量、原单责任处理及退回隔离保管。新增原件维修批次、返工复检和归还签收；项目进度入口位于最前。新增“训练资源与排期”，接入明确容量/准备收尾资源、单次/小组/维护时段及客户预约候补、单人调课与当次请假。新增“训练计划与当次课程”，保存项目模板/个人计划不可变版本及实际课程记录、核对和中止。新增“家庭练习与阶段复评”，连接明确家长发布、实际提交来源、专业反馈和固定资料的人工复评。新增“长期档案与复查”，衔接资料与已核对复评，显示眼别/检查条件时间轴、明确复查安排及逾期，保留实际处理与结案后续。新增“联系与预约”，独立保存联系授权、人工实际联系与回执、失联接管/延期和预约到店关联。新增“外院资料与转介”，保存外院原资料/无法测、绑定原版本的专业确认和转介联系、改期与结果。新增“接触镜 / OK 镜专项”，保存明确条件来源版本、客户评估与本版同意、专业采用及撤回保护；已接专业原参数/订片来源与实际到货批号，贯通原加工质检、签收及出库，已接原产品护理材料、实际掌握和专业核对放行，已接原镜片复查/异常与专业明确继续、调整、暂停停用，关联原复查/转介/实际联系；后续更换归档继续推进。第一阶段仍未整体验收。

## 运行

需要 Node.js 24；运行依赖全部来自 Node 与浏览器原生能力。

```sh
npm ci
npm run demo
npm start
```

打开 http://127.0.0.1:3000。demo 只在空库初始化两个虚构门店、六个可直接登录账号及两个人员状态样例、八位虚构客户及六个分阶段场景、14位家庭联系人及2份修订档案，并在本机终端一次性输出随机密码；请保存密码。在已有示例库重复执行，只补充缺少的虚构案例、人员状态与家庭资料样例，不重置账号、不覆盖现有数据；与示例编号冲突会回滚并报告。非示例账号库拒绝扩展。默认数据库 data/workbench.sqlite，已被 Git 忽略。不要录入真实资料。

账号为 demo-manager（负责人）、demo-front（前台）、demo-professional（专业人员）、demo-other（B 店负责人）、demo-parent（只授权小林）、demo-practice-parent（只授权小安的家庭练习演示）。家长不显示内部周期或联系人资料，只能查看明确发布给本人的练习和共享反馈。

开发自动重启：npm run dev。可用环境变量 HOST、PORT、DATABASE_PATH、NODE_ENV；`.env.example` 是参考，程序不会自动加载 `.env`，请由启动环境提供变量。默认只监听本机；生产模式被明确阻止，需先完成正式架构和身份接入。
