# Optical Workbench · 视光业务工作台

根据[产品设计蓝图 V1.1](https://optical-workbench-blueprint.wenjinuu.chatgpt.site)启动的第一阶段基础开发版。V0.4 使用浅色、鲜明的蓝色主色，薄荷绿、紫色与珊瑚橙区分业务。当前可保存客户档案、周期草稿、家长授权与多周期到店，管理本店人员及账号安全、查看六个分阶段虚构场景，上传/下载/撤销客户附件，并保留资料修订版本，提供门店/岗位/家庭权限与审计。第一阶段仍未整体验收。

## 运行

需要 Node.js 24；运行依赖全部来自 Node 与浏览器原生能力。

```sh
npm ci
npm run demo
npm start
```

打开 http://127.0.0.1:3000。demo 只在空库初始化两个虚构门店、五个可直接登录账号及两个人员状态样例、八位虚构客户及六个分阶段场景，并在本机终端一次性输出随机密码；请保存密码。在已有示例库重复执行，只补充缺少的虚构案例与人员状态样例，不重置账号、不覆盖现有数据；与示例编号冲突会回滚并报告。非示例账号库拒绝扩展。默认数据库 data/workbench.sqlite，已被 Git 忽略。不要录入真实资料。

账号为 demo-manager（负责人）、demo-front（前台）、demo-professional（专业人员）、demo-other（B 店负责人）、demo-parent（只授权小林）。家长不显示内部周期或联系人资料。

开发自动重启：npm run dev。可用环境变量 HOST、PORT、DATABASE_PATH、NODE_ENV；`.env.example` 是参考，程序不会自动加载 `.env`，请由启动环境提供变量。默认只监听本机；生产模式被明确阻止，需先完成正式架构和身份接入。

## 验证与备份

```sh
npm run check
npm test
npm run backup
```

31 个集成测试覆盖会话撤销、跨店/越动作/越家庭拒绝、关系撤销、重复写入、共享电话独立档案、原子回滚、持久化和基础数据恢复。CI 已配置，实际远程运行状态见 PR。

电脑与手机浏览器验证脚本为 scripts/browser-check.mjs；可将 Playwright 安装到独立临时目录，设置 PLAYWRIGHT_MODULE_PATH 指向其 index.mjs（绝对路径），再运行 npm run test:browser。CHROMIUM_PATH 默认 /usr/bin/chromium。测试自建内存库，截图写入已忽略的 data/browser-check/，不会改现有档案。

backup 在 backups/ 生成一致性 SQLite 快照，不含明文密码。恢复开发库时先停止服务，将当前数据库及其 WAL/SHM 文件移至独立归档目录，再把选定快照放到新的 DATABASE_PATH 并重新启动；先核对 integrity_check、客户/周期/审计数量和账号，不直接覆盖正在运行的数据库。正式备份/恢复目标和账目演练尚未完成。

保留蓝图的 50 个任务与 287 条需求。正式文件存储与扫描、正式身份/组织及资质职责、专业检查/报告确认与审批、正式部署以及后续 P03–P10 均未完成；扣次与退款等待规则。本轮没有改动蓝图站点，其公开进度快照仍是原版本。

六个流程阶段是明确标注的固定演示样板；它们不会生成已确认的专业计划、收款或扣次。底层关联客户、周期草稿和到店记录可以实际查询。家长授权管理需要负责人、关系与操作依据；家长只看基本资料。一次到店可关联多个同一客户的周期，结束到店不结束周期。

V0.3 内部附件支持 PDF、PNG、JPEG 和 UTF-8 文本，单文件1 MB；下载逐次校验门店/动作权限，撤销后停止访问。资料记录区分员工记录、外部资料转录和家长自报转录；每次修订新增不可变版本，要求当前版本编号与依据，旧版本与附件引用保留。家长当前仅看基础身份资料，内部附件和资料版本不会直接对外发布。

本地附件字节、元信息、版本引用都保存在同一SQLite库；备份包含文件与历史，无需额外拷贝上传目录。示例扩展补充6个虚构文本附件、6份资料记录及8个版本（其中2份有修订），不覆盖已有记录。

V0.4 负责人可新增本店员工、修改姓名/岗位/启用状态、重置密码和撤销登录会话，变更要求当前人员版本与操作依据。编辑、停用、重置及撤销会话立即停止旧登录；本人修改密码保留当前会话，撤销其他会话。新增/重置密码后，除读取本人信息、退出和改密外，服务端拒绝操作。密码不会进入响应、审计或幂等结果。

新增虚构入职/停用样例（demo-onboarding / demo-inactive）；样例密码不输出，可由负责人重置后演示，原有五个账号仍使用既有密码。人员变更不修改客户或历史记录。当前人员管理仅限单店，不包括新建门店、跨店调动、正式身份验证、通知邀请或专业资质审批。
