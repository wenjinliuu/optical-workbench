# Optical Workbench · 视光业务工作台

根据[产品设计蓝图 V1.1](https://optical-workbench-blueprint.wenjinuu.chatgpt.site)启动的第一阶段基础开发版。V0.16 使用浅色、鲜明的蓝色主色，薄荷绿、紫色与珊瑚橙区分业务。当前可保存客户档案、周期草稿、家长授权与多周期到店，管理本店人员及账号安全、查看六个分阶段虚构场景，上传/下载/撤销客户附件，并保留资料修订版本，提供门店/岗位/家庭权限、审计及运行恢复工具。新增独立“配镜与商品”入口，维护商品目录并实际保存订单明细、固定原到店需求和资料版本，支持草稿修订、取消及历史。第一阶段仍未整体验收。

## 运行

需要 Node.js 24；运行依赖全部来自 Node 与浏览器原生能力。

```sh
npm ci
npm run demo
npm start
```

打开 http://127.0.0.1:3000。demo 只在空库初始化两个虚构门店、五个可直接登录账号及两个人员状态样例、八位虚构客户及六个分阶段场景、14位家庭联系人及2份修订档案，并在本机终端一次性输出随机密码；请保存密码。在已有示例库重复执行，只补充缺少的虚构案例、人员状态与家庭资料样例，不重置账号、不覆盖现有数据；与示例编号冲突会回滚并报告。非示例账号库拒绝扩展。默认数据库 data/workbench.sqlite，已被 Git 忽略。不要录入真实资料。

账号为 demo-manager（负责人）、demo-front（前台）、demo-professional（专业人员）、demo-other（B 店负责人）、demo-parent（只授权小林）。家长不显示内部周期或联系人资料。

开发自动重启：npm run dev。可用环境变量 HOST、PORT、DATABASE_PATH、NODE_ENV；`.env.example` 是参考，程序不会自动加载 `.env`，请由启动环境提供变量。默认只监听本机；生产模式被明确阻止，需先完成正式架构和身份接入。

## 验证与备份

```sh
npm run check
npm test
npm run backup
```

V0.5 备份同时生成核对清单，可用 npm run backup:verify -- 备份路径 校验，并用 npm run restore -- 备份路径 新目录 恢复。完整步骤见[恢复操作手册](docs/recovery.md)。

162 个自动测试覆盖会话撤销、跨店/越动作/越家庭拒绝、关系撤销、重复写入、共享电话独立档案、原子回滚、持久化和基础数据恢复。CI 已配置，实际远程运行状态见 PR。

电脑与手机浏览器验证脚本为 scripts/browser-check.mjs；可将 Playwright 安装到独立临时目录，设置 PLAYWRIGHT_MODULE_PATH 指向其 index.mjs（绝对路径），再运行 npm run test:browser。CHROMIUM_PATH 默认 /usr/bin/chromium。测试自建内存库，截图写入已忽略的 data/browser-check/，不会改现有档案。

backup 在 backups/ 生成已校验的一致性快照与清单。恢复只写入尚不存在的独立目录，保留原库并撤销恢复副本的全部会话；核对通过后才指向新 DATABASE_PATH 启动。原库和快照保留，切换前核对授权变化；正式恢复目标和完整账目演练尚未完成。

V0.3 内部附件支持 PDF、PNG、JPEG 和 UTF-8 文本，单文件1 MB；下载逐次校验门店/动作权限，撤销后停止访问。资料记录区分员工记录、外部资料转录和家长自报转录；每次修订新增不可变版本，要求当前版本编号与依据，旧版本与附件引用保留。家长当前仅看基础身份资料，内部附件和资料版本不会直接对外发布。

本地附件字节、元信息、版本引用都保存在同一SQLite库；备份包含文件与历史，无需额外拷贝上传目录。示例扩展补充6个虚构文本附件、6份资料记录及8个版本（其中2份有修订），不覆盖已有记录。

V0.4 负责人可新增本店员工、修改姓名/岗位/启用状态、重置密码和撤销登录会话，变更要求当前人员版本与操作依据。编辑、停用、重置及撤销会话立即停止旧登录；本人修改密码保留当前会话，撤销其他会话。新增/重置密码后，除读取本人信息、退出和改密外，服务端拒绝操作。密码不会进入响应、审计或幂等结果。

新增虚构入职/停用样例（demo-onboarding / demo-inactive）；样例密码不输出，可由负责人重置后演示，原有五个账号仍使用既有密码。人员变更不修改客户或历史记录。当前人员管理仅限单店，不包括新建门店、跨店调动、正式身份验证、通知邀请或专业资质审批。

V0.5 新增“运行与恢复”：负责人查看本店本次启动的请求计数、近期耗时和故障编号。服务端生成请求编号，错误提示与结构化日志关联；日志不含请求内容、身份凭据、客户编号或堆栈。统计窗口最多200个请求，故障列表最多20条，重启清零；正式持久监控/报警待定。

V0.6 可编辑客户姓名、出生日期、主要联系人和电话，每次保存来源与依据并生成新版本，保留原客户编号和周期/附件关联。历史档案不可覆盖或删除，升级前已有资料标为来源未登记的存量基线。负责人/前台可新增、编辑、停用家庭联系人，员工按本店读取；联系人与家长账号查看授权分别管理，共用电话只提示核对、不合并。检索包含有效联系人的姓名和电话。演示脚本补充备用/停用联系人和基本资料双版本，重复运行保留后续修订。完整家庭成员、付款身份与监护证明核验尚未实现。

V0.7 客户总览显示完整的周期草稿、待结束/已结束到店、有效联系人、资料与可访问附件数量，提供最近登记到店的时间/目的/状态。历史时间轴串起档案、周期、到店、联系人、资料、附件与查看授权，按类别和UTC日期筛选、每页20条加载更早记录，并可定位当前页面的对应资料。时间轴使用已有记录与有限动作的审计投影，不新增业务状态；缺失的早期依据/操作人明确标出，不重建未知历史。家长不读取内部总览或时间轴。电脑和手机支持独立滚动、键盘操作与折叠查看。

V0.8 周期草稿支持需求修订、来源/依据和不可变历史。新到店捕获所选周期需求版本；修订到V2之后，旧到店继续引用V1，新到店引用V2，不改变周期类型或状态。前台登记时校验所看到的版本，陈旧选择拒绝并提示重新读取；周期编辑也可读取最新需求、保留未提交内容后核对。升级前到店未保存版本的关联标为未知，不把当前需求补成历史。虚构案例增加两份周期修订、一次修订后复访与第二种周期，展示跨业务关联。用户暂缓亲自测试，开发验证继续，业务整体验收仍待完成。

V0.9 新增通用任务分派/本人接收/带依据转交、个人与本店队列、客户交接历史和时间轴。固定客户/周期/到店与当时需求版本；转交后重新接收，业务执行仍待开始。停用接收人提示负责人安排交接。六个虚构样例展示协作阶段，重复初始化保留后续操作。用户后期集中体验；开始/暂停/退回/完成、岗位候选/时限/通知及专业规则继续推进。
