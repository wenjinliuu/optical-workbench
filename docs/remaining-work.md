## 建议继续顺序

1. **继续已复现的运行安全修复**：V0.95登录限流回收与有界化完成后，按runtime-security-next-plan.md继续V0.96新建活动数据库私有权限；主业务仍按R01–R10真实资料恢复，不补造临床或财务规则。
2. **同时准备真实规则与表单**：R01/R02机构岗位及检查实表；R03/R04扣次/缺席/中止/冻结/效期/退款优惠的算例；R05营业排班/容量/系列变更/补课；R06财务与提成口径；R07监护/跨店/保留；R08正式部署与恢复；R09支付消息设备；R10售后质量责任。提供决定人、依据、日期和实例，才将等待规则的功能转为实际执行。
3. **按规则补两个主业务闭环**：训练的预约→到店签到→实际执行→权益扣次/撤销→复评/调整；视光的检查→专业确认→处方/报告→验配/质量/交付→复查。继续复用原客户/周期/到店/版本和实际事实，资金、权益、临床与实物分别确认。
4. **补运营与完整未启动模块**：审批通知、仓库矩阵/员工财务、团体筛查，再做分析、接口、迁移与完整长期可视化；按原依赖与门店实际优先级推进，不删减原范围。
5. **最后按T10集中验收与受控试运行**：用户可继续暂缓逐轮操作；开发验证持续进行，正式上线前完成全业务/异常、手机电脑/权限、资金库存权益一致性、恢复和长期图表验收。

每完成一个步骤同时更新仓库与网页勾选、剩余范围和验证证据，执行 `progress:verify`；同步规则见 [progress-tracking.md](progress-tracking.md)，实际回执见 progress-sync.json。
