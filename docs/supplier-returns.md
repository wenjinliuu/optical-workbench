# V0.42 · 原隔离批次分批退供与供应方收件

T07.01/T07.02、W5-N3/N4/N6 的开发切片，沿用原采购、收货、质量和库存来源。安排、实际交出、供应方收件分别记录；费用、责任、退款/贷项、正式供应政策和资格均不预设。

## 商业安排与原批容量

负责人建立固定原质量办理、原收货、原供应方及原单位数量的退供安排。每版明确人工退供依据、安排去向、可选联系资料和来源引用，固定观察版本/质量事件、收货资料、采用时两个业务序列和退供共同序列。未知联系人保留 null。草稿、提交及批准尚未交出量占用本批商业容量，多份安排不能超额；安排和批准不移动库存。

商业提交、批准检查当前原质量和收货来源。批准或驳回且未发生交出时可明确重开草稿；资料变化后可重开，再明确采用当前版本，不能直接批准旧来源。未交出安排可取消；部分实际交出后只能明确停止剩余安排，旧实际事实不改。停止或取消不自动解除实物隔离。

## 实际交出与供应方收件

负责人逐批记录已经发生的交出时间、数量、实际接收人、实际去向和可核对事实，固定原批准/安排版本和原批次，捕获原库存、销售出库、批次及商品退供序列。必须有原明确批准，实际时间不能早于批准，数量不能超过批准未交出量、本批剩余或实际隔离量。后来收货资料、观察、供应方启停或商品名称变化不抹去已经批准安排的实际负向事实；原单位和原来源保留。

supplier_return_handoffs 是原隔离实物的实际退供转出账。可用/预留/销售出库账各自保持；实际隔离及在库量扣除已经交出的数量，不先解除隔离、不伪造 receive/isolate 哨兵库存事件。供应方后续分批实际收件固定原交出 ID，累计不得超过其数量，时间不早于实际交出；负责人或前台可转录可核对收件事实，收件不再扣减库存，不推定资金结果。

外部编号和本次来源唯一标识独立，均可未知。已知来源唯一标识在原安排交出或原交出收件范围防重复；编号可重复，未知不声称实现外部自动去重。所有写入与审计/幂等缓存同一事务；请求体读完后重核当前权限、原来源和商业正向门禁。

## 剩余实物复检与放行

原质量办理数量和旧意见保持不可变，保护数量减去本批实际退供转出。每个观察/质量事件保存当时实际剩余数量与退供前缀。部分交出后，后续合格或放行须人工形成采用当前剩余实物的新观察版本并实际复检。全部实际交出的批次不能新造实物观察或正向放行。

本批仍有未交出商业安排时不能放行；先明确取消或停止剩余安排。经当前观察实际合格复检后，负责人只解除剩余实物数量的隔离；不会把原始总数量恢复为可用库存。另有同商品库存不能重用已经退供的原收货数量。普通库存和收货入库增加退供来源并发租约，不能静默覆盖实际退供变化。

## 历史、恢复与展示

schema39 增加九张表：supplier_return_plans/versions/events/handoffs/receipts，purchase_quality_version_return_context、purchase_quality_event_return_context、inventory_dispatch_return_context、inventory_event_return_context。原库存累计账保持，当前投影扣除实际退供；旧销售出库以当时退供前缀核对隔离快照，新出库采用新的实际隔离量。

非空 schema38 升级保留旧业务行，退供事实为空，只添加新账空序列 0 的技术上下文，不能据此声明旧世界没有退供。恢复核对全部159表、商业/实际共同流水、固定批准与原资料、逐批数量/时间、原库存/出库与同毫秒前缀、正向放行前商业余量及当前保护数量。恢复清零会话。

七个独立虚构阶段从采购收货/原批质量进入：草稿、已批准未交出、部分已交出、全安排已交出待收件、供应方分批已收、部分交出停止余量、商业驳回仍隔离。重复初始化保留既有记录，不改旧阶段。电脑/手机表单明确记录实际事实，来源变化保留填写且禁用保存，退出清空窗口。

开发验证入口：21项退供专项、28组浏览器（含新退供）、全量自动检查、语法检查、CLI新建/重复/备份核验/独立恢复。具体通过证据记录在交接；完整批次/仓位分配、扫码、调拨、盘点、成本、正式资格和业务验收仍未完成。
