# P01 运行安全续接入口

V0.94闭合的是现有handler诊断样例差集，不能据此推断全部公共运行代码都没有工程问题。2026-10-18用户再次要求继续推进，本轮按已有授权核对登录和本地数据文件，只处理已复现问题；R01–R10真实业务规则与整体验收仍待资料。

1. V0.95：登录限流旧地址不清理、无地址数量上限。原源码5000虚构地址两分钟后仍有5001条记录；见login-limiter.md与本轮验证。
2. V0.96已修复：新建活动数据库路径以`0700`目录、排他原子保留的`0600`文件创建；SQLite WAL/SHM在Linux、`umask 022`下实测均为`0600`。既有目录/数据库内容与权限保持，`:memory:`不触碰文件系统；并发路径准备仅一个进程认领新文件。范围与验证见[database-file-permissions.md](database-file-permissions.md)。
3. 下一步核对同库初始化的锁等待：本轮用两个独立Node子进程同时打开同一个全新虚构库，3次均出现一个成功、另一个`ERR_SQLITE_ERROR: database is locked`。现有`busy_timeout=5000`写在`journal_mode=WAL`之后，应先核对锁可能在等待策略设置前发生的路径，以及迁移事务内的重查。修复范围限本地CLI/服务的有界等待、原子初始化和失败清理；这不是正式多实例部署决定，不能借此声称R08已确认。V0.96只解决路径权限，不把初始化锁误记为已解决。
