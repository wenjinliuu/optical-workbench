# P01 运行安全续接入口

V0.94闭合的是现有handler诊断样例差集，不能据此推断全部公共运行代码都没有工程问题。2026-10-18用户再次要求继续推进，本轮按已有授权核对登录和本地数据文件，只处理已复现问题；R01–R10真实业务规则与整体验收仍待资料。

1. V0.95：登录限流旧地址不清理、无地址数量上限。原源码5000虚构地址两分钟后仍有5001条记录；见login-limiter.md与本轮验证。
2. 下一V0.96：新建活动数据库缺少显式私有文件权限。在Linux、umask022下独立虚构库复现：新数据子目录0755，数据库与WAL均0644。备份/恢复已经显式使用0700/0600，活动新库应采用同样的最小访问原则。只修复新建目录/数据库文件的权限，明确处理并发新建，保留既有文件内容及权限，不跟随推断正式数据保留或部署方案。验证新建、已有库、`:memory:`、WAL/SHM、迁移和恢复，不输出数据库内容或凭据。
3. 随后核对同库初始化的锁等待：本轮用两个独立Node子进程同时打开同一个全新虚构库，3次均出现一个成功、另一个`ERR_SQLITE_ERROR: database is locked`。现有`busy_timeout=5000`写在`journal_mode=WAL`之后，应先核对锁可能在等待策略设置前发生的路径，以及迁移事务内的重查。修复范围限本地CLI/服务的有界等待、原子初始化和失败清理；这不是正式多实例部署决定，不能借此声称R08已确认。若V0.96已解决该路径，不重复交付。

先补完当前精确CI、原Site、三份下载及新回执，再进入下一项。后续只沿实际复现的安全/一致性/恢复问题推进，不重复诊断或筛选维度；没有独立问题时记录所缺真实依据，禁止空交付。主业务下一入口为门店实际检查项目/字段/单位及确认岗位，用户可在本轮工作期间用文字补充；未知不填默认临床字段。
