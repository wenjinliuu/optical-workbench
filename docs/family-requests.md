# V0.56 家庭预约与请假意向

T08.02第一切片。当前有效授权的本人从固定客户提交预约或请假意向，申请标题、种类、说明明确填写。预约须明确本人期望UTC起止区间；请假可以明确时间未知，保留null，不假造原预约。原预约尚未关联，提交不占资源名额，不取消原预约、不触发扣次、补课、退款或通知。

员工在本店工作台明确接收、要求补充说明、回复或结束核对。每次选择动作、对外回复及独立内部依据；接收或回复不等于批准。本人只可撤回自己的未结束意向，不修改原始提交。原内容、希望时间、接收人和客户固定，后续动作追加流水。本人要更改意向，可明确撤回后另建；不能用修订覆盖原提交。

## 当前范围

家庭列表、详情及历史只限当前有效授权客户且原提交人是本人。同客户的另一监护人不能查看或撤回这份申请。员工负责人和前台可在本店核对，专业人员和其他门店不可读写。公开回复与内部依据分开；家庭不接收员工内部原因、员工身份和门店全局序列。当前开发角色不代替正式家庭身份核验或实际门店审批权限。

授权撤销后家庭全部读取与写入失效，原员工记录保留；员工仅可结束内部核对，不能继续向无有效授权的本人回复。采用家庭返回内容前重新验证授权和本人申请来源，迟到的旧内容不重新显示；退出登录清空页面、弹窗和请求状态。

## 契约

- 家庭GET/POST /api/family-requests/family/:customer：本人申请分页/明确新提交。
- 家庭GET /family/:customer/context：当前有效授权来源及本人该客户已有申请数；提交带expected_authorization和expected_count，相同幂等意图重放一次，并发重复预览只允许一个新申请。
- 家庭GET /family/:customer/authorization?expected_source：返回内容采用前验证授权及本人申请来源。
- 家庭GET /family/:customer/:id：原申请与公开流水有界历史；POST /:id/events仅明确withdraw。
- 员工GET /api/family-requests、/:id：本店申请及完整内部历史；POST /:id/events明确acknowledge/request_information/respond/close，expected_sequence与expected_revision匹配。

查询默认30最大100，后页同source_token，未知或重复参数拒绝。正文等待后重新核对身份/角色/门店/安全修订，事务内核对当前会话、家庭授权、申请数量/修订及员工序列。审计、原提交事件和幂等结果同事务，失败全部回滚。完整数量不会由一页截断。
