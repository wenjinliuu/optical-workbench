# V0.57 家庭原预约事实公开

T08.02第二切片。员工从固定家庭申请明确选择同客户、同门店的真实原训练预约，填写对外说明及独立内部采用依据。公开操作只保存关联和固定原事实；原计划、资源版本、容量、重复客户及时间冲突仍由原排期流程执行。本功能不会新建、转正、调课、取消或请假原预约，也不生成扣次退款、实际到店或消息送达。

原申请与原预约ID固定在公开根上。每次版本固定原预约当次事件修订、原计划/周期身份与版本、原时段事件版本及当次起止时间，同时捕获原schedule_journal与家庭申请流水前缀。候补保持waiting，不推断名额；实际leave与普通cancel按原动作分别展示，不把取消改称请假。原排期后来变化不会静默替换旧公开说明；来源变化标明原关联变化，员工明确核对后公开新版本。

仅原申请提交者且当前有效授权的本人可读取公开最小内容。原资源名称、员工、训练计划说明、内部依据、价格及其他客户预约不进入家庭响应。公开根与旧版本撤回保留员工历史；后来公开新版不恢复先前已撤回版本的本人访问。本人授权撤销立即阻止家庭读取和新的公开，员工仍可负向撤回。

## 接口与页面

- 员工GET /api/family-bookings/requests/:request/options：同客户完整有界原预约选项，各项当前原来源令牌；不按本人期望时间自动匹配或预选。
- 员工GET /requests/:request：关联公开根的分页；GET /:id：当前或数值旧版本及有界原历史。
- 员工POST /api/family-bookings、/:id/versions、/:id/events：明确公开、新版、撤回。正文等待后重新核对身份、角色、门店及安全修订，事务内核对当前会话；正向原申请/本人授权/原预约守卫在缓存返回前与事务内执行，公开序列及根修订在实际保存时核对。
- 家庭GET /api/family-bookings/family/:request：本人明确公开的最小原预约；GET /family/:request/authorization?expected_source：采用返回内容前重新核对本人授权/原申请/原预约和公开历史。

默认30，最大100；后页必须同来源，未知/重复参数及假审批字段拒绝。原申请详情内集成入口。员工选择器初始空白，新版说明为空白；明确续读来源保留输入，固定原预约不可在同一根改换。家庭页面把本人期望意向和原排期实际事实分开；迟到撤权响应会清空整个受保护详情，退出登录清空新增弹窗。
