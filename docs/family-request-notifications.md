# 原申请通知与原版回执反向入口（V0.63）

对应T08.02 / M16-F04。原本人申请详情现在可读取明确采用该申请的具体通知版本和每版主动已读回执。没有保存来源的通知不靠相似标题或文字补造关联。一份通知后来改为采用另一份申请时，旧申请只显示确实采用自己的旧版本；按具体版本保留当时来源、公开内容、回执和当前原通知版本提示。

家长仅当前授权本人且仍可公开读取的版本；员工保留本店旧关联及撤回状态。全部/主动已读/未主动已读筛选与完整版本总数、当前可读未读版本数一致。同源分页同时绑定原申请、筛选、当前原申请修订、通知/回执和授权，源变动要求重新读取。

GET `/api/family-request-notifications/family|staff/:request` 返回只读反向投影；`/authorization?expected_source=:adoption_source` 在采用异步响应前再次检查。服务端验证原申请所属本人/客户/门店与当前权限；此入口拒绝所有写入，也不生成已读或结束申请。

通知原接口GET `/:root?version=:version` 现在准确读取指定原版本并显示当前原通知修订，不把旧版入口跳到最新。撤回界限仍检查，家长不能通过固定版本参数读撤回旧内容；员工可核对历史。本人主动标记该版已读沿原POST接口，旧版回执不会替代新版未读，原申请反向列表会刷新。固定旧版视图只读原版，不从旧版界面误办当前通知修订/撤回。

桌面和手机共用同一事实。原申请内打开具体通知/标记已读后恢复原回执列表；已知撤权导致已读失败时，同时清空嵌套通知和原申请敏感内容。迟到响应在采用前复核，不显示被撤回或失效授权内容，退出清空。读取和查看都不自动记已读，不改变实际预约、权益、临床同意或外部送达。

本轮无新迁移，schema56/234表（233数据表）保持；反向关系来自既有明确来源。复用八原来源虚构阶段，读取和重复种子不改业务记录。14项新专项覆盖关系隔离/具体版本/角色和门店/已读分页/当前源拒绝/撤回/只读/恢复，加原通知和原来源合计48相关专项。`npm run test:family-request-notifications-browser` 核对电脑/手机、原版查看、回执刷新与筛选、嵌套撤权和迟到响应；完整CLI与全量结果记录在progress/handover。业务整体验收保持待后续。
