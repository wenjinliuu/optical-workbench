本轮为T04.01/T04.04/T04.05的开发切片。原50任务、287需求、依赖和业务验收范围保留；负责人/前台登记实际动作，专业人员执行本人分派案例，家长不读取内部记录。示例全部虚构。当前仅本地开发与同一草稿PR。

## 原签收与实际出库

每条出库固定既有deliver签收记录，继承其原加工工单、客户、门店、订单版本/原行、商品版本和单位。只能登记已实际离店的数量，累计不得超过该行原签收数量；一个签收可分次出库，未出库量持续保留。商品后来调价/停用不替换原来源。负责人/前台可登记，专业人员可查询。

有原单有效全量预留时，从该原预留行扣减实际reserved，即使加工曾标记purchase也不能绕过原单占用。没有有效预留时，从已登记的实际available扣减；采购到货/加工完成/签收不会自动生成库存。缺实物账或数量不足先核对实际入库，服务项目不进入实物出库。原单实际出库后，整单新增预留/释放停止，原预留头与剩余原行保持，后续逐项处置另行实施。

inventory_events原入库/隔离/预留/释放快照保持不可变；inventory_outbounds另存实际出库与出库后数量。当前实物投影为：原available减累计available出库，原reserved减累计reserved出库，原quarantined保持；on_hand为三者之和。原分配流水的reserved仍表示原全量分配，当前实物reserved表示尚未离店占用；禁止将历史分配快照直接用作当前实物数量。

库存读取和订单预留stock_versions同时携带sequence与outbound_revision；出库不增长原库存sequence，故两个版本必须共同核对。库存操作写入仍按原分配流水连续快照，实际投影及SQL守卫再核对非负数量；后续真实入库/隔离/新订单预留均使用当前实物判断。出库保存还核对原单预留revision及该签收已出库量。旧客户端未提供outbound_revision按0处理，发生出库后须重读，不接受旧数量。

出库历史保留当时库存依据、独立连续出库版本、扣减来源、数量、操作人/时间与依据。库存历史显示操作时实际可用/预留投影，原分配字段仍保存在库内；出库历史从原签收批次独立查看，当前库存不能混算历史快照。

## 售后登记与责任处理

维修、重做、投诉、退回是需求分类；登记不是方案批准，也不自动生成退款或新的专业参数。每个案例固定原签收批次及客户/门店，涉及量不得超过原签收量；每批次至多一个活动案例，结束或取消后可新建，重开旧案例需确认该批次没有另一个活动案例。历史超过50条时仍查询全部记录判断活动案例。

状态为open待安排、assigned待开始、running处理中、paused暂停、resolved处理记录已结束、cancelled已取消。负责人/前台分派责任人及可选预计日期；开始/暂停/恢复/结束由当前责任人或负责人执行。前台可追加活动案例沟通记录；专业人员只能追加本人负责案例。负责人/前台可取消和明确重开，重开回到未分派状态。分派需本店有效员工；首次改密未完成可接受分派但不能越过改密门禁执行。

每次变更保存连续不可变事件和规范状态快照，note/reason明确保存；预计日期未知保持null，不能造默认承诺日期。结束处理记录描述本次处理留痕，不代表维修、质检、退款或库存处置全部完成。

## 退回件独立隔离保管

负责人/前台选择原签收批次的实际inventory_outbounds来源，明确本次退回数量、实际返还人及说明/依据。所有案例合计同一出库来源退回量不得超过原出库量；本案例累计不得超过本案例涉及量。未登记实际出库的商品不能伪造退回库存，不能借用另一批次/另一原行的出库来源。

receive_return追加独立售后隔离保管记录，展示于案例及商品库存流水窗口。它不增加正常库存的available/reserved/quarantined，也不回滚原出库；售后保管数量单独核对，不能混作正常隔离库存。正常库存“解除隔离”只处理原inventory_events隔离，不会处理售后退回件。案例结束、取消或重开不清除已接收实物，不执行自动退款、重新销售或报损。

下一V0.22继续T04.05的维修执行、重新质检/签收和隔离处置衔接。正式处置批准、维修重做专业确认、费用/退款审批、采购批号/序列号、索赔召回及回访规则按实际规则逐项实施；当前没有宣称完整质量追溯或售后闭环验收通过。

## 接口与共同入口

| 接口 | 行为 |
| --- | --- |
| GET /api/dispatch/receipts | 本店原签收出库队列，pending/partial/dispatched、字面搜索、完整匹配计数、有界分页 |
| GET/POST /api/fulfillment/events/:id/dispatch | 原签收及库存投影/完整分页出库历史；显式数量、依据及四项当前读数 |
| GET/POST /api/fulfillment/events/:id/aftercare | 原签收固定来源/最近案例/全部案例数量与活动案例；创建需expected_case_count |
| GET /api/aftercare/cases | 本店案例、状态/逾期/本人分派筛选、完整匹配计数、字面搜索及有界分页 |
| GET /api/aftercare/cases/:id | 原单来源、当前责任/状态、隔离保管量、可退回的原出库来源及分页历史 |
| POST /api/aftercare/cases/:id/events | expected_revision、明确action、处理说明/依据，分派或退回字段仅对应动作允许 |

新“批次出库”“售后与追溯”导航，以及质检已签收行、签收回执、原单和客户时间轴共用来源。重读冲突时保留数量、类型、标题、处理说明、责任人/日期、原出库和返还人填写。退出或切换客户后迟到的授权响应不重建原数据。桌面侧栏导航滚动保留账号退出入口；手机沿用自适应导航。
