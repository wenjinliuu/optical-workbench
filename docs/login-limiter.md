# 登录限流记录有界化 · V0.95

T01.04 / N07 运行保障修复。原登录逻辑只在相同地址再次访问时过滤该地址的时间戳，不会删除离开后的地址。在原源码逻辑上用5000个虚构地址复现：两分钟后加入一个新地址，仍保留5001条地址记录。

`src/login-limiter.mjs` 在每次登录检查时清理全部过期地址，并将进程内记录限制为4096个地址、每地址最多10个时间戳。这个上限仅是本地开发程序的内存保护，不是门店容量或正式运行指标。容量满时拒绝新地址，保留已有地址的有效限流记录；已有地址仍按自身剩余次数办理，不通过驱逐旧记录让地址轮换绕过限流。过期后释放空间，不运行后台计时器，也不持久化地址。

既有每个实际连接地址60秒内10次有效格式登录尝试、成功失败合并计数、HTTP429和`RATE_LIMIT`保持。成功登录不重置次数；拒绝不延长窗口。只采用socket实际连接地址，不信任调用方填写的`X-Forwarded-For`或`X-Real-IP`。间隔使用进程单调时钟，系统日历跳动不重置限流；登录会话的真实到期时间继续使用原日期时钟。

达到限流时不创建会话、Cookie或审计，也不撤销已有有效会话。进程重启重新计数，与原本相同；正式部署的代理可信范围、分布式限流和容量仍待R08实际架构，不从请求头或当前技术上限推断。schema60、业务表、固定引用、恢复格式和业务验收保持。

验证：`test/login-limiter.test.mjs`覆盖精确滑动边界、过期地址清理、4096上限/地址轮换、已有额度、独立实例和日历跳动；`test/foundation.test.mjs`新增实际HTTP限流、原会话保留、零新增会话/审计与伪造转发地址测试。`npm run test:login-browser`在电脑1440×1000和手机390×844验证错误凭据重试、第10次成功、退出、第11次拒绝、提示/按钮恢复、日志脱敏与无溢出。云端运行诊断任务同时执行登录浏览器流程。
