# ADR 001：本地基础验证，正式架构待确认

日期：2026-10-07。状态：本地开发选择已执行；生产架构待定。

optical-workbench 是正式系统的代码仓库。设计站点是需求基线。当前仓库初始仅 README，无既有技术栈；没有从其他聊天读取到技术约定。

首个切片使用 Node 24 ESM、原生 HTTP 与 node:sqlite、语义 HTML/CSS/浏览器模块。不需要第三方运行依赖，可直接验证数据、事务和授权；前端与 /api 契约分离，后续可按正式 UI 框架选择迁移。数据库文件默认 data/workbench.sqlite。迁移逐版本事务执行，SQLite 开启外键、WAL 和写入等待。

身份使用本地开发账号、随机初始化密码和 scrypt 哈希；8 小时服务端会话，浏览器仅 HttpOnly、SameSite=Strict cookie，数据库只存令牌哈希。写请求校验会话 CSRF；错误密码限速。单店员工通过当前数据库角色/门店授权，家长按有效客户关联授权，不开放内部字段或周期内容。manager 不具备专业检查确认动作。角色/关联直接数据库变更仅供测试，管理 UI 尚未实现。

默认监听 127.0.0.1，只允许 development/test 模式。NODE_ENV=production 启动失败，因为正式身份、TLS、存储、审计保护、规模与运维尚未确认。本地内存登录限速和 SQLite 单进程事务不作为多实例生产设计。当前幂等结果不自动过期，保留/清理策略待定；列表与审计只返回前 100 条，正式分页待实现。

审计和业务写入在同一事务，审计表触发器拒绝应用级修改删除；这不代表抵御数据库管理员的篡改，生产外部审计保存与保留规则待确认。本轮只新增基本资料，没有业务修订/快照接口，不将基础表误当专业版本服务。

应用只服务四个显式静态资源，不接受磁盘路径映射。输出 CSP、禁止框架嵌入、no-store、nosniff；用户资料由 textContent 呈现。生产网络和身份由下一 ADR 决定，当前不连接真实数据、设备、支付或消息。

备份使用 VACUUM INTO 生成事务一致快照；自动测试重新打开原库和备份，检查完整性与客户/周期/审计数量。此证据仅覆盖本轮基础表，不能代替权益、资金、库存账和正式 RPO/RTO 演练。

## V0.3 公共资料基础

本地附件以SQLite BLOB保存，元信息与文件字节、版本引用、审计在同一事务，不存在磁盘文件与数据库部分成功的问题；一致性备份包含全部字节。1 MB限额及明确MIME/头标识/UTF-8校验防止任意类型上传；文件名禁止路径与控制字符，下载强制附件并使用sandbox。无公开静态文件路径，下载前逐次验证会话、岗位、门店及撤销状态。

内部资料版本保留内容、来源、修订依据、创建人时间及附件引用；expected_version拒绝陈旧写入，数据库触发器拒绝改写/删除旧版本。当前仅通用资料，没有创建专业确认、处方、报告发布或审批语义。附件撤销仍保留字节和旧版引用，访问许可在读取时判断。

这是本地基础选择；正式对象存储、扫描、容量、保留期限、数据库管理员防篡改和发布后的家庭文件范围仍待确定。1 MB不是生产规模承诺。
