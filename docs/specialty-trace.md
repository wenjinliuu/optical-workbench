# V0.35 专项订片、原参数与产品批号

T06.04 / W4-N2–3 的具体开发切片。W4-N4 的护理指导和 W4-N5–6 的专业复查、更换、停用及长期归档继续办理；整项业务验收待完成。

## 原来源与专业核对

复用零售商品、订单、参数交接、工单、质检、签收和实际出库，不复制客户或商业账。当前专项原单须含镜片，可含关联服务，不含其他实物；固定同客户、同门店、同需求原版本。由当前专业责任人明确关联尚未发生预留、收款或加工的原单，不能给已有执行事实补原授权。每项镜片须有明确人工参数交接并专业核对，单位和专业值未知不补造。

specialty_order_links 固定原订单与专项身份。specialty_order_approvals 连续追加当时评估版本/责任修订、条件及同意全店序列、原同意版本、已核对参数版本/序列、核对人/时间/说明。普通订单修订不能改已关联原单；明确取消仍走原单保护。暂停、恢复、责任变化、同意撤回/重新取得、参数变化均需专业明确重新核对。条件来源退役或换版须重新建立明确专项来源，不静默重绑。已开工后新的评估版本不能替换原执行依据，后续重订/原单变更处理继续开发。

## 到货批号与质量

specialty_product_lots 固定实际 processing_events.receive、原工单/行/商品版本与数量。各批合计不超过本次实际到货量，重试不重复占用。实际供应到货与商品库存入库是两个事实。批号、序列说明、生产方、供货方及来源资料明确转录；批号未知保留 unknown 和 null，不推定序列、效期或自动换算计量单位。

specialty_lot_versions 追加批号来源更正，原未知版本和固定数量保留。更正说明不改原实物分配，不宣称实现全部数量纠错/采购验收、序列自动校验或召回规则。新合格质检、签收和出库前，本行全部已到货数量须有明确可访问批号来源；质量项目及判断仍由原质量流程记录，批号登记不代表合格。到货、失败质检及批号原事实可以在同意撤回后继续留档，不恢复执行或临床状态。

## 跨模块执行与历史

API 在读取请求体后、缓存重放前和事务内核对当前专项来源；SQLite 原生门禁分别保护新预留、实收、加工安排/开工/完成、合格质检/返工执行/签收和出库。资金误录纠正、库存释放和实际到货保留各自原规则。不产生默认退款、费用、临床指标、专业许可或自动通知。

specialty_execution_refs 自动固定每次受保护动作的专业核对版本、当时专项/订片/参数序列、加工修订与批号原版本快照。后来撤回或更正只改变新的执行条件，恢复按照捕获的当时序列核对历史，不用当前意见替换旧事实。新增五表进入 schema32 备份、独立恢复及客户时间轴；跨店/家长读取拒绝，内部角色按动作核对，审计/幂等和业务同事务回滚。

## 展示与验证

原配镜订单增加“专项订片与批号追溯”，专项档案可以定位原单。电脑、390px 手机可查看固定来源、专业重新核对、实际到货批号、追加更正及旧版本。来源冲突保留填写并要求从新来源明确开始，不自动套用新评估或参数；退出后迟到响应不重新展示内部数据。

三个实际保存的虚构阶段：订片来源已核对；实际到货、批号待补；批号贯通质检/签收/实际出库。单独虚构商品/订单，不修改已有客户、评估同意和商业事实。重复初始化保留人工修改。

专项检查覆盖权限/门店、未执行原单、参数变化、同意撤回与缓存重放、原生门禁、批号未知/更正/容量/撤销访问、开工后评估变化、责任暂停恢复、审计回滚、原执行批号快照、schema31 非空升级、备份/独立恢复和重复展示。正式临床表单/单位、机构人员条件、产品质量标准及后续业务规则仍依真实来源逐项办理。
