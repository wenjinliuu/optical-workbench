# 实际出库原批来源与客户追溯 · V0.46

原采购收货、人工原件身份和仓位观察、实际销售出库共用固定来源。从原收货可查明确采用该批的已交付客户、签收和原订单版本。实际可用库存出库时可明确选取1至30个当前有效的原批观察；本次数量、可核对交出来源与说明均由实际办理人填写，未选取不补造原批。

原批引用与原实际出库、审计和幂等响应同事务，仅扣减原实物一次。固定原收货资料、商品版本/单位、原观察版本/事件、当时质量与退供前缀及实际交出依据；后来更正资料或撤回观察不改写已经发生的出库。成功实际出库的同意图重试返回原负事实，即使原观察后来撤回；当前身份、门店和重置密码仍在正文后核对。

同一原收货的多个仓位共用原匹配数量减实际退供、已明确售出和质量保护后的上限，同一原观察不重复选取。已经明确售出的原件不能靠另一箱同SKU库存重新进入原批在库或质量保管。观察数量和这些上限都不证明今日原件仍在库，不累计多个观察为当前余量；旧未跟踪出库的原批来源仍未知。原单预留暂未建立原批身份依据，不能借用可用观察，不领取完整独占分配或仓库政策。

负责人/前台保存本店实际出库，专业人员可读本店原批追溯，家长和跨店不能读取；追溯只含客户姓名、编号和原订单，不增加联系电话或临床资料。

- GET `/api/inventory/products/:id/batch-sources`：当前原批候选完整总数，默认30/最大100，后续页须 `expected_source`；来源变化拒绝静默替换。
- 原 POST `/api/fulfillment/events/:id/dispatch` 可选增加 `batch_sources`、`batch_source_note`、`expected_batch_sequence`、`expected_custody_sequence`。每行只含 `custody_id/custody_version_id/custody_event_id/quantity/source_reference/note`，完整行合计等于本次实际出库数量。
- GET `/api/inventory/outbounds/:id/batches`：固定原出库最多30个原批引用，旧未记录明确显示未知。
- GET `/api/purchase-receipts/:id/delivered-batches`：原收货已明确交付客户/原单，默认30/最大100，后续页须 `expected_sequence`，今日批次在库量保持NULL。
- 原出库历史和客户时间轴共用固定原批引用，不另造一条库存事件。原收货和出库页面均有客户追溯入口；固定原观察按原数字版本打开，不依赖前100条窗口。

schema42七表包括实际声明、原批引用、旧未记录技术边界、原观察/质量根与原收货/质量事件的批次前缀。旧质量退供前缀保留NULL未知，旧记录不被追溯标注；追加不可变、同毫秒相互捕获、历史原保护/已售上限和完整数量配对进入180表备份/独立恢复。

七个独立虚构SKU和原采购/收货/原订单演示待实际出库、未记录原批、部分/完整交付、出库后观察撤回、后来资料修订、部分销售后重新实际核对。原业务旧行和SKU余额保留，重复初始化不覆盖后来操作。验证入口为21项实质专项、827全量、32组浏览器及180表CLI；正式生产身份、仓库政策、完整矩阵、扫码盘点调拨成本与业务整体验收保持待完成。
