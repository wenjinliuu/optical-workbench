# V0.23 售后重做/换货与新商品交付

原售后详情“重做/换货与新商品交付”可以为同一客户创建独立新订单，明确商品版本、数量、本单单价和资料引用，再提出本次商业安排。负责人明确确认业务安排后，复用既有预留、实收、供货加工、质检、签收和实际出库。每个新实物行的实际出库量等于原新单数量，且原案例处理中，才能明确登记本安排交付完成。

原件维修、旧件保管、新商品交付、资金及专业批准分别记录。本功能保存商业安排，不自动产生已批准专业方案、免费更换、退款金额或旧件处置。新订单只允许同一客户/本店、独立于原单、尚无库存/资金/加工记录、最新未取消且全部实物的草稿。原案例涉及量明确填写，按原案例计量单位保护累计未取消安排容量；新单各行使用自己的数量与单位，不用不同单位的数量合计替代专业或价格规则。

| 接口 | 用途 |
| --- | --- |
| GET /api/aftercare/cases/:id/replacements | 完整案例/全案例sequence、有界安排列表及最近历史，limit/offset分页 |
| GET 同路径 /options | 同一客户当前可关联的新单及版本，读取需要售后管理权限 |
| POST 同路径 | kind、quantity、new_order_id/version、instructions、note/reason；expected_case_revision/expected_sequence共同保护 |
| GET /api/aftercare/replacements/:id | 固定新单/每行已出库、工单入口、当前状态、分页历史 |
| POST 同路径 /events | approve/cancel/complete，expected_revision/expected_sequence/expected_case_revision及note/reason |

状态：pending待商业确认 → approved已确认 → completed明确新商品交付完成；pending/approved可明确cancel，但已有占用/实收/活动加工或实际出库时不能直接取消来源。须先按原流程释放未用预留、纠正真正误录或取消尚未执行的工单；不能以误录作废代替实际退款或撤销已交付商品。

前台/负责人关联和取消、登记交付，商业确认仅负责人；专业人员读取内部来源，家长拒绝内部接口。本批次原件维修执行角色不因此被改写。新单待确认不可预留、登记实收或建立加工；确认后实际到货/加工、质检/签收和出库要求案例处理中，暂停/结束时须明确恢复/重开并开始。常规资金记录与实际执行分别核对。

活动安排锁新订单版本，保留单价/原明细，普通修订/取消被API和SQL拒绝。明确取消安排后来源版本仍保留，须先修订新订单，才能作为普通独立订单继续。原案例涉及容量只有取消释放，已完成交付仍占原涉及量，重开原案例不会再造一份免费更换。

020新增安排、不可变事件及共享操作引用三表。全案例case_sequence连续，单安排revision连续；创建/批准/取消/完成固定当时案例版本。新单每条预留、资金、工单、加工、质检和实际出库操作由SQL自动捕获固定plan_revision与case_revision，真实记录与审批/案例状态共同核对。业务、引用与审计同事务；幂等重试先回放原响应。原SQL结构和旧业务行不改写，升级不产生伪批准。

恢复检查固定原客户/原签收案例/独立新单、原涉及容量、事件转换/序列、实际每行出库、取消保护、业务操作批准引用及完整覆盖。删除引用或变更语义后即使还原触发器，恢复校验仍拒绝。客户时间轴保存原案例和新单版本；新订单页面可回到来源案例，冲突重读保持新订单选择、类型/数量/说明及本次记录，失效新来源不得自动替换。退出清空表单/列表，迟到授权响应隔离。
