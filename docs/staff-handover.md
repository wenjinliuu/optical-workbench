# 本店员工业务责任与交接 · V0.49

负责人按员工核对当前保存的业务责任，逐项进入原业务办理交接。汇总13类：通用岗位任务、加工原单行、售后、个人训练计划、当次课程、长期档案、复查、联系、客户预约、转介专业责任、转介联系责任、待复核外院资料、接触镜专项。它是当前责任查询，不创建新的执行、临床判断、收支、库存或员工资格。

停用或重置密码的员工仍保留原责任，账号状态和待改密单独显示。实际指定员工的责任与岗位候选任务分别统计，后者不能当成该员工已接收。责任条目与不同客户数量分别统计；同一转介的专业和联系责任是两项。取消、已完成或明确结束的原业务离开当前待办，历史仍在原模块保留。未记录日期保留未知；明确日期已过只作日期提示，不补预设办理时限、风险等级或通知。

默认每页30，最大100，员工与责任完整总数不截断。搜索按文字匹配，支持岗位、账号、是否有责任和业务类型。源凭据同时覆盖本店账号与安全状态、客户显示资料和13类原事件/完成来源；后续页及打开原操作前重新核对，变化时须从第一页读取。不让另一门店的活动扰动本店凭据。仅负责人读取，同店接待/专业账号不通过人事管理权限，家长及跨店拒绝；没有专业正文、联系人地址、密码、报价或资金明细进入总览响应。

通用任务“办理原任务转交”使用既有原任务接口、当前修订、原接收人候选核对和审计。接收人显式选择，提交不会直接接受或恢复执行：原 running 转为 paused，新员工 awaiting；原 blocked 保留阻塞原因和状态。读到较新修订时拒绝静默采用。专业计划、加工、专项同意与专业责任沿各原业务操作核对，工作台不把本地岗位当作资质或自动替代专业责任。

- GET `/api/staff-handover/employees`：`q/active/role/duties/limit/offset/expected_source`，本店完整人员/责任/候选任务总数。
- GET `/api/staff-handover/employees/:id/responsibilities`：`q/kind/limit/offset/expected_source`，原客户、记录ID/原行、原修订/版本、当前状态/明确日期及种类统计。
- 实际转交继续 POST `/api/tasks/:id/transfer`；新员工接收、开始/恢复仍分别办理。其他业务继续使用其原API，原专业及来源保护保持。

本轮不新增账表，schema44/199表继续核对和恢复。七个独立虚构任务展示待接收、执行中、暂停、阻塞、已转交待新员工接收、停用后原责任、岗位候选未指定；只新增一位演示停用员工及七任务20事件，旧账号/原任务与资金库存保持，重复初始化不重置。实际交接仍保留到原客户时间轴，不另造重复时间轴事件。
