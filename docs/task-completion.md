# 通用任务完成依据与条件校验草案

状态：V0.11设计草案，尚无完成接口、完成状态或下游自动任务。当前已实现的异常/交接/执行与其独立；本文件不作为任何专业、财务或权益规则的授权。

下一技术切片先保存通用资料核对的完成依据，复用customer_id、task_id/revision、cycle_id/version、visit_id及document record_id/version。提交依据引用明确已保存的资料版本，记录员工、来源、说明与提交时间；后来修订资料不改旧引用。仅客户资料不能被另一客户任务引用，附件授权每次读取按现有门店和动作检查。

完成条件应独立版本化，每个任务固定适用的条件版本和来源。先考虑明确说明必填、必需资料版本存在、必需附件可核对、本人已接收且正在执行、没有未解决阻塞或取消这类可直接核验的通用条件。条件不能从任务标题或演示场景猜测；专业职责、检查字段/单位/缺测原因、处方/报告确认和审批需依据rules.md的真实规则，未确定时显示待明确，不能当作通过。

| 场景 | 条件与处理预期 | 需保留的证据 |
| --- | --- | --- |
| 资料核对 | 条件明确且固定，当前本人、版本完整和正常执行，才允许提交依据 | 资料不可变版本、员工身份、任务修订和依据来源 |
| 条件缺失或阻塞/取消 | 列出缺失/不符项，保留可修订草稿，不能完成或推进 | 校验结果、条件版本、失败定位；失败不生成任务事件或下游 |
| 多人或重复提交 | 同一当前修订只有一次成功，原输入同键重放原结果 | 共同事务和幂等；任务/依据/审计一致 |
| 资料后来修订 | 既有依据保留原版本；重新核对须另有明确记录 | 原引用和后续版本分别可查 |
| 专业确认或依赖推进 | 条件和职责未授权时保持待处理 | 专业规则来源及版本，不用通用核对替代 |

后续可再实施完成条件预览/校验和依据草稿，但保存依据不应自动结束周期/到店、发布报告、收款/退款、扣次、出入库存或创建下一任务。串并行汇合、循环、取消后下游关系、完成撤销、时限日历和审批分别需要具体模板与规则；未定义的依赖不能画成已存在的业务流程。

开发验证需覆盖员工/门店/家庭边界、固定资料版本/客户不匹配、资料后来修订、陈旧任务/条件版本、异常不推进、幂等与事务回滚、不可变时间轴及独立恢复。业务方测试按用户安排留至后期；T03.02及原依赖链不因此整体验收。
