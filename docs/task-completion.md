# 通用任务核对依据与完成条件

状态：V0.15已实现通用条件、依据版本、明确提交及不可变完成产出、追加说明更正、显式后续任务关联及已保存多层任务链。范围固定为generic_record_review。专业职责、专业确认/审批和真实业务完成规则继续单独落实。

负责人或前台显式设定通用核对范围与资料/附件要求。当前有效岗位的本人接收后，可保存缺项草稿；暂停或阻塞允许留待补，取消或完成禁止保存。条件、草稿各自保留版本，引用同一客户的document_versions.id及attachment_id；原V1不会被后来V2替换。

保存和只读校验均不完成任务。POST check检查当前输入且persisted=false、completion_enabled=false；GET当前保存依据及保存结果仅在当前本人、岗位可用、已接收、运行中、无异常、尚未完成、当前条件/任务修订、说明/必需引用及附件访问都满足时completion_enabled=true。界面有未保存说明/来源/引用变更时禁止提交，即使预览校验通过。

本人填写产出说明和提交依据，明确勾选确认并点击提交。POST completion/submit仅接受所见任务修订、已保存条件/依据版本和产出说明，不接受未保存依据或专业确认字段。事务内复核有效会话、身份、最新版本和附件访问，再保存task_completions、审计及幂等响应。陈旧、缺项、阻塞、取消、非本人和撤销附件均不能完成。审计失败全部回滚；不同键竞争仅一个完成产出，同键原响应重放。

完成是独立终态：completion_status=completed、effective_execution_status=completed。task_events与work_tasks原字段是完成前最后执行快照，不添加伪造暂停/重写旧事件，也不递增执行revision；task_completions独立记录实际完成时间与操作人并固定原修订。当前完成记录决定队列/看板状态，完成任务从运行/暂停计数排除，后续全部交接、执行、异常、条件/依据写入在服务端及数据库禁止。

产出固定条件、依据、完整任务上下文、原标题/资料版本、附件稳定元信息与内容指纹、提交时通过的核对项，以及产出说明、原因、员工id和时间。引用附件事后撤销不重写完成记录；界面区分当时固定产出与当前访问撤销。操作人id固定，姓名沿用当前账号显示名。原产出不覆盖；追加通用说明更正按下述权限独立留存，当前不重新打开完成任务。

客户任务、个人/本店队列、列表/八列看板/状态流程共用已完成状态与完成筛选，完整计数不受100条展示上限影响。交接历史增加完成产出；客户总览和时间轴读取实际完成记录。恢复校验结构、外键、连续版本、引用清单、原执行快照和完成快照/指纹一致，事后员工改岗/停用/改名或附件撤销保留历史。

V0.14保留原18个任务，新增已完成说明更正/沿用原产出待接收/采用更正V2待认领三个虚构阶段。全量21任务/60执行事件、7条件/7依据、5资料引用/5附件引用、2完成/2更正/2后续关联；重复初始化不覆盖后续处理，V0.13非空升级不补造更正或关联。

原提交人（当前有效本店员工）或门店负责人可以追加通用产出说明更正。仅output_summary/reason可更正，不能改原条件、资料/附件、操作身份、完成时间或终态。更正版本独立，首次所见版本0；原完成指纹和当前更正版本在事务中核对，陈旧/相同说明/越权拒绝，审计和幂等同事务。界面同时呈现原产出、当前更正和完整历史，原操作人id固定、姓名为当前显示名。

门店负责人或前台填写新任务名称/说明、接收人或候选岗位和分派依据，明确创建关联后续任务。继承原customer/store/cycle_id+version/visit_id/context_basis，不重新套用当前需求版本。来源固定原完成指纹、分派时采用的原产出或更正版本及说明；后来的更正不改已分派来源。旧附件事后撤销仍可记录更正/安排联系，后续任务不复制条件/依据或声称已经核对，须另行配置/保存并本人接收/开始。

新任务、初版分派事件、不可变来源、审计及幂等同事务。所见更正版本变化时拒绝并保留填写重读，不自动生成任务；不同新意图可以明确分派多个任务。当前关联表达来源，不等于正式业务串并行/汇合/循环规则。完成产出列出后续任务（最近100条及完整总量），子任务显示当时来源版本和说明、提供原产出入口；时间轴与恢复核对全部新记录、连续更正、固定来源/上下文/时间及无循环。
