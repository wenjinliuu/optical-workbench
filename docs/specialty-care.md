# V0.36 原产品护理指导与掌握情况

T06.04 / W4-N4 的开发切片。指导内容、实际练习、专业核对和明确放行分别保存。专业复查、异常跟进、更换停用与长期归档继续推进；整项尚未验收。

护理记录固定专项原单、实际合格质量批次、原商品与数量、原评估/批准及质量当时的批号版本。交付前记录只关联尚未实际签收的原批；交付后须选实际签收来源，不能给旧交付补护理授权。掌握要求来自人工明确的原规则，是否要求演示必须选择，不使用默认要求。材料、实际指导当事人与身份来源、摘戴护理内容、观察、异常提示、联系说明、实际时间和下一步由实际资料提供；未知掌握情况保留，不生成方法、阈值或复查频率。

接待可以转录待核对资料，掌握判断及已有专业意见的修订由当前专项专业责任人办理。专业核对不等于放行；符合明确原要求并完成核对后，专业另行明确放行。未知和未接受不能放行；原规则明确要求演示时，需补练也不能放行。原规则不强制演示时，专业仍须另行明确核对与放行，不能自动豁免。

新增指导版本返回待核对，原材料和旧版放行人/时间保留。暂停和恢复分别追加，恢复回到待核对；结束本条护理不结束原专项、周期或自动退款。交付前已有护理要求的合格批次，新签收需要有效放行，结束记录不能绕过要求；原签收带护理来源时，新的实际出库也需有效护理来源。原评估同意、订片批准或材料访问变化阻止新执行。没有护理记录的历史批次不补造规则或重写原交付。

四张表 specialty_care_records / versions / events / execution_refs 进入 schema33、客户时间轴、备份及独立恢复。每次签收和出库固定当时的护理版本、专业修订和全店护理序列；后续资料修订、暂停或同意撤回不替换旧事实。恢复按捕获的临床、订片、参数及护理序列核对，能区分同一毫秒发生的前后动作。API 和原生数据库均保护来源、掌握与放行，审计/幂等写入和业务同事务回滚。

电脑和手机入口在原单“专项订片与批号追溯”内的“护理指导与掌握情况”。支持追加实际指导、专业核对/放行/暂停/恢复/结束和原材料版本；来源冲突保留填写，重新从明确来源开始。退出后迟到响应不显示内部资料。三阶段虚构展示分别为交付后资料待核对、交付前仍需补练、原指导专业明确放行；独立追加自己的原单和记录，重复初始化不改已有来源。

验证覆盖掌握与放行分离、明示要求、权限与原来源、签收/出库即时保护、材料访问撤销、版本和暂停恢复、缓存/审计回滚、同毫秒原签收来源、非空 schema32 升级、四表独立恢复及分阶段重复展示。真实专业规则、资质、指导资料及后续专业处置依实际来源办理。
