# 订货与加工 · V0.19

T04.03的本地开发切片。工单固定原订单版本、客户、门店和逐行实物商品版本；读取原单关联的到店及需求版本。普通加工说明不等于已确认处方或专业加工参数。原任务依赖保留，整项业务验收待完成。

## 原单分项与安排

负责人/前台从未取消的原单建立工单，必须安排全部实物行，服务行排除。商品、数量和原位置由服务端读取，不能提交另一数量或合并重复商品行。每单工单serial连续，同一原单最多一个未取消工单；此前未执行计划取消后可明确建立新工单，旧来源和历史保留。

每行明确供货方式stock/purchase，加工方式internal/external/none，本店责任人、供应来源、预计日期及说明。purchase或external必须有供应来源名称；这是本地文本记录，未接供应商主档或采购接口。预计日期可明确留空（未知），否则为2000–2099年的有效YYYY-MM-DD；未完成项早于当前UTC日期提示逾期。安排可指派本店有效员工；首次改密账号不能执行业务动作，工单展示责任人当前可用状态。

每行保存14个固定字段：position、product_id、product_version、quantity、supply_mode、processing_mode、supplier_name、assignee_id、due_date、instructions、received、started、completed、delay_reason。事件保存完整不可变快照，revision连续。arrangement和执行历史可按版本读取，原商品规格、单位和版本使用原单引用，不用后来目录变化替代。

## 分批数量与交期

到货/备料(receive)、开工(start)、加工或备货完成(complete)分别登记本次数量，始终满足0 ≤ completed ≤ started ≤ received ≤ 原行quantity。不同原行独立处理，重复SKU也保留原位置；不把副、片、个等不同单位相加。采用none加工方式的实物也需要明确记录备货进度，不能自动认为已完成或可交付。

| 工单状态 | 已保存记录依据 |
| --- | --- |
| planned | 尚无分项到货/备料 |
| partial | 已有到货/备料，尚未开工 |
| running | 已有开工，仍有未完成项 |
| awaiting_qc | 全部实物行完成，等待后续质检 |
| cancelled | 负责人明确取消尚未到货/备料的计划 |

delay保存当前延期原因和新预计日期（允许未知），clear_delay明确解除说明并保留日期及数量。延期/逾期与实际执行状态并行显示，不能抹掉已完成数量。已到货项锁定供货方式和供应来源；已开工项锁定加工方式及说明。未完成项可明确改责任人/交期并保留原执行记录，完全完成项只读。全单完成不自动质检通过、签收、收款或确认成交。

## 订单、库存与资金约束

活动加工工单保护原单修订/取消，API与数据库同时拒绝；取消加工计划不自动取消原单，也不解除已有资金或库存约束。只允许取消所有行received=0的计划；已经执行的工单保留，后续按变更/返工流程处理。

stock项登记备料前必须已在同一原订单版本预留全部实物商品。任一stock项已有received后，禁止释放原预留，避免工单保留备料而库存已被他单占用。后续出库、损耗、变更和返工需另行衔接。purchase项到货是工单记录，不自动新增库存入库流水；员工需要独立登记实际库存入库。加工动作不更改payment_events，不推导应收、尾款、专业确认或退款规则。

## 权限与接口

本店负责人、前台、专业人员可读工单。负责人/前台安排和到货；开工/完成仅当前分项责任人或负责人；延期/解除允许负责人、前台或当前责任人；取消仅负责人。跨店返回404，家长拒绝内部工单。保存依据必填，严格拒绝额外字段，事务内重查有效会话/改密/岗位，CSRF、幂等键、当前版本及审计一起保护写入。

| 接口 | 契约 |
| --- | --- |
| GET /api/processing/jobs?q=&state=&mine=&limit=50&offset=0 | 字面搜索原单/客户/标题/工单号；state为all/planned/partial/running/awaiting_qc/cancelled/delayed/overdue，mine为all/assigned；完整匹配数量，最多100条分页 |
| GET /api/processing/assignees | 本店有效员工及改密状态，最多500条，truncated明确标记 |
| GET /api/retail/orders/:id/processing | 当前原单实物行、活动工单、最近50个工单来源及完整数量 |
| POST /api/retail/orders/:id/processing | expected_order_version、expected_job_count、lines、reason；lines仅position及六个安排字段，不接受原数量/商品修改 |
| GET /api/processing/jobs/:id?revision=&limit=50&offset=0 | 当前或指定历史快照，current_revision明确当前记录；历史分页独立，最多100条 |
| POST /api/processing/jobs/:id/events | expected_revision、action、reason；非cancel需position；receive/start/complete需quantity；plan需包含六个安排字段的plan；delay需due_date |

六个安排字段为supply_mode、processing_mode、supplier_name、assignee_id、due_date、instructions。事件action为plan/receive/start/complete/delay/clear_delay/cancel，create仅建立工单内部生成。数量为1–999的整数，依据最多300字，供应来源最多120字，说明最多1000字。陈旧原单/工单返回409，不同意图复用同键409；同意图重试返回原结果；审计或幂等落库失败全部回滚。
