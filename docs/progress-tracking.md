# 仓库与设计网页的同步规则

2026-10-12 用户明确要求：每完成一个开发步骤，仓库项目进度和网页项目进度/勾选必须同时跟进。这是每轮交付的必做项。

唯一进度源是 `codex/phase-one-foundation` 分支的 `docs/progress.json`。设计网页沿用原 Site：
https://optical-workbench-blueprint.wenjinuu.chatgpt.site

1. 开发验证通过后更新具体版本交付勾选、相关任务/需求的实现状态、剩余范围、验证证据、阻塞和下一入口；同步 capability-map 与 handover。
2. 在原设计 Site 的源码检出目录执行 `node scripts/sync-design-progress.mjs --site-root <原站点检出目录>`。它复制唯一进度源和共用进度渲染器，再调用站点原 `generate-docs.mjs` 生成网页快照、完整执行文档、需求追踪表和三份下载。不得手改生成文件来补勾选。
3. 检查原18模块、7流程、50任务、287需求和原依赖/正文仍完整；核对电脑/手机上的版本、勾选数、默认项目进度入口、剩余范围与下载。
4. 推送原站点绑定源码、打包静态产物并发布同一 project_id，保持既有访问范围。网站进度发布与正式业务后台上线分别管理。
5. 发布成功后运行 `npm run progress:verify -- --receipt docs/progress-sync.json`。程序实际读取线上网页快照及三份下载，比较仓库 JSON、原需求正文/归属、当前状态和完整执行文档。核验失败不能称两处已同步。
6. 将发布版本/源码提交/部署 ID 补入核验回执和交接，推回原业务分支，才结束该轮。回执是同步证据，不能替代业务验收。

本轮首次恢复时网站为V0.57/57项，仓库为V0.59/59项；补齐V0.58和V0.59，不新增第60项业务交付。

勾选表示具体开发切片完成并有验证依据。原完整任务的实现、整体验收各自记录；部分实现保持进行中，只有符合原前置、完整范围与业务验收证据才能记已验收。不能用59次迭代推算整体完成百分比。

如果源码、发布或核验被阻塞，记录仓库版本、网页实际版本、缺少的同步内容、原因和恢复入口，明确告诉用户该轮同步未完成，不以口头承诺替代上线核验。
