当前为本地开发业务系统，使用虚构资料。对应T05.01及T05.04的独立技术部分，原任务依赖和整体验收待完成。项目模板、个人计划、现场课程、权益账、预约和资金是独立记录。

## 页面与角色

“训练计划与当次课程”提供本店模板、计划、课程检索/状态筛选/分页和匹配总数，也可从客户档案进入并按客户筛选。负责人及专业岗位维护项目模板；专业岗位创建计划，只有当前计划责任人调整和确认/暂停/恢复/结束。负责人、前台、专业岗位可为已确认计划登记实际到店课程和明确执行人。

固定专业岗位执行人开始/暂停/恢复及记录实际；未开始可明确重新分派。课程核对由当时计划版本的责任人完成，即使新计划已换负责人。负责人可中止未结束课程，员工可追加说明。开发岗位不代替真实资质，家长没有内部训练入口。服务端门店/动作/当前会话/首次改密门禁在写入事务再次检查；处理中撤销登录不写入业务。

## 模板与计划版本

模板创建后修订生成新版本，可启用/停用；已有计划保留原版本，新选项目必须是本店当前启用版。明确保留旧计划已采用的模板允许继续使用旧版，模板变更不会静默替换。页面“采用模板说明”必须显式点击，个人项目说明另外保存。

个人计划固定客户、训练周期、需求版本以及可选原到店捕获的需求，不能换客户或需求来源。每版保存人工评估来源/说明、目标、标题、1–30个项目及固定模板版本/说明、责任人、可选频率/时长/复评文字说明、固定资料版本和附件。未填写的安排为未知，不自动生成临床项目、评估结论、频率或复评日期。

create→draft；confirm→active；active可pause→paused，paused可resume→active。draft/active/paused可end→ended，需先明确处理所有ready/running/paused课程。调整revise生成新draft版本，必须再次明确确认；ended不可调整。结束不改变周期草稿、收费、权益或预约。固定附件撤销访问保留历史引用，新选/确认/恢复须可访问。

详情列最近100版，历史事件每页50条并可加载更多；课程来源可直接定位任何当时计划版本。查看旧版同时显示当前版本和当前状态，旧版不提供计划写操作。

## 当次现场课程与实际记录

创建课程必须选择同客户/周期、已登记未结束的实际到店，捕获它保存的需求版本；这一版本独立于个人计划的原需求版本。只允许从当前active计划创建，捕获当时计划/项目/资料版本、创建时计划修订、执行人，之后不得改来源。

ready可assign或start→running；running可pause→paused或record→recorded；paused可resume→running；recorded可correct追加更正或confirm→reviewed；ready/running/paused可abort→aborted。note保留当前状态并追加说明。记录与核对分开；reviewed/aborted不可更改实际记录。开始需要人工填写已经发生的UTC时间；记录/更正必须人工填写实际结束时间，不早于开始且不晚于登记时点。

实际记录固定形状：

```json
{
  "items": [{"position": 1, "actual_minutes": null, "completion": "partial", "feedback": "人工记录反馈"}],
  "additional_activity": null,
  "feedback": "当次整体反馈",
  "actual_minutes": 0,
  "ended_at": "2026-10-08T09:30:00.000Z"
}
```

每个原项目位置恰好一项，完成情况completed/partial/not_done/unknown；分钟数null代表未登记、0代表明确0，范围0–1440。实际总分钟数人工记录，不由开始结束差值或项目相加推导。逐项反馈、整体反馈、额外活动/差异另外保存，不覆盖计划内容。评估/记录来源明确区分员工记录、外部资料转录和家长自报转录；没有设备自动采集或家长提交接口。

新计划不改旧课程：旧ready不能按失效的计划版本首次开始，应明确中止并按当前计划另建；已经running的旧版课程可以保存已发生实际记录，新计划draft/active不抹掉现场事实。计划明确paused阻止实际record/resume，结束前要处理未结束课程。开始/恢复要有可用原资料附件和未结束实际到店；已经发生实际可记录，即使之后附件撤销，但核对需要原引用可访问。旧课程仍由原版本责任人核对。

## 并发、恢复与衔接

所有写入使用X-CSRF-Token、Idempotency-Key，严格拒绝未定义字段。模板修订带expected_version；计划调整/状态及创建课程带expected_version、expected_revision、expected_session_sequence。课程事件带expected_revision、expected_plan_revision、expected_sequence（计划内所有课程全序列）。竞争只允许匹配当前版本的一方写入，业务/引用/事件/审计/幂等同事务回滚。冲突重读保留表单、原模板选择、引用、实际未知/0和UTC时间，再由操作人明确核对。

schema24新增十个不可变表及两个current视图。原生约束检查同店客户来源、连续版本/事件、合法动作、实时人员、时间与实际项目。计划事件捕获当时课程全序列，课程事件捕获当时计划修订，双向回放区分同一毫秒先后并拒绝篡改未来来源。历史人员角色可能后来变动，恢复核对固定关系而非用当前岗位重写过去。历史附件撤销采用已有时间戳；同毫秒撤销没有旧数据序号，不能据此重建未知顺序。

所有新表纳入备份/校验/独立恢复，恢复副本会话清零。schema23非空升级不补造训练记录或改旧表，客户时间轴提供原计划版本及课程定位。退出清空训练页面和弹窗，迟到的授权响应不恢复客户资料。
