# 原申请明确手工发布服务通知（V0.64）

对应 T08.02 / M16-F04。员工在本人原申请详情点击“从本原公开版本明确发布通知”，明确采用当时所见的本申请公开修订。编辑器限定这份申请，标题、公开正文和内部依据均由员工另行填写；打开入口或读取来源不保存通知。

来源预览保留原选择。编辑期间出现新回复，原保存接口以当前申请修订拒绝陈旧来源；输入及旧选择保持。员工明确读取来源后只加入本申请当前修订，仍需手工选择新版再保存，不自动替换来源。该入口直接读取这份原申请，原申请位于通用来源列表后续分页时也能使用，不会误选第一页另一申请。通用通知编辑仍支持明确不关联或选择其他原申请。

保存复用原服务端 POST 的门店/员工岗位、指定本人当前授权、当前通知来源、当前申请修订、幂等/原子审计与不可变来源保护。成功后回到原申请，读取新通知的固定原版本及主动已读回执；正文与内部依据分开。失效本人授权拒绝保存并清空编辑内容，重新读取原申请后隐藏发布按钮。家长没有员工发布入口，只能从原申请打开已公开通知并主动标记原版已读。

原申请状态/事件、实际排期、权益和资金均不因发布或已读而修改；外部渠道尚未接入。退出及迟到响应受原会话和原详情生命周期保护，不能重建已经清空的编辑内容。本轮无新迁移和示例数据，schema56/234表（233数据表）保持，复用八原来源虚构阶段。

验证入口 `npm run test:family-request-notification-publish-browser` 使用真实本地 API/数据库核对桌面/手机、后续分页原申请、空白手工输入、回复冲突/保留选择与明确新版、单份固定来源通知与原事实不变、原入口刷新/回执、授权失效及家长私有隔离、迟到退出。另跑原来源/通知/反向浏览器与48项相关服务端专项，全量和发布记录以 progress/handover 为准。整任务及业务验收继续待用户集中进行。
