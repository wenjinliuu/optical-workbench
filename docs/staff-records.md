# V0.50 员工原来源、明确安排与培训事实

T07.03 的本店负责人录入入口。固定员工 ID、门店和记录类型，不覆盖旧版本；账号名称和岗位显示的是当前资料，系统不补写历史人事名称快照。完整业务验收、正式专业核验、人事政策、跨店代办与财务规则仍待后续。

| 类型 | 保存的人工事实 | 保留的未知与业务边界 |
| --- | --- | --- |
| qualification | 名称、证件号来源状态、颁发来源状态、颁发日期状态、到期日期状态、范围及待核事项 | unknown 对应 null；输入原来源不等于资质核验，不授予专业许可 |
| shift | 人工安排开始/结束 UTC、地点及职责说明 | 是明确安排，不推导可预约容量或自动指派 |
| absence | 人工安排开始/结束 UTC、休假/缺勤与覆盖安排说明 | 不定义审批政策，不自动转交原业务 |
| training | 实际发生时间状态、培训名称、参与事实、结果说明 | 实际时间须已发生；unknown 对应 null；not_recorded/attended/completed 不代表专业资格 |

全部新版本均手工填写标题、原来源引用、来源说明、本版事实、依据和下一步。引用只存文字，不访问外部 URL、不借用客户附件。固定记录的类型和员工不可更改。撤回解释仅追加事件，不注销员工或实际事实，后续明确新来源可追加新版本。员工记录没有客户归属，不生成虚构客户时间线；原业务交接仍保留其原时间线。

GET /api/staff-records/employees/:id：q/kind/status/limit/offset/expected_source，完整总数、四类型有效/撤回数量；默认30条、最多100条。GET /api/staff-records/:id：version 可指定固定旧数值版本，limit/offset/expected_source 为原事件历史分页。后续页必须采用同一 source_token，员工当前资料或本店记录流水变化时 409。另一店活动不改变本店来源。

POST /api/staff-records 新建；POST /:id/versions 追加手工新版本；POST /:id/events action=withdraw。所有写入要求 expected_employee_source、expected_sequence、reason、next_step；已有原记录另需 expected_revision/expected_version。新建另带 staff_id/kind；新版本带 title/data/source_reference/source_note/record_note。字段严格按类型，未知状态与 null 必须对应；休假/班次结束晚于开始；实际培训时间不在将来。日期比较是事实格式检查，不推定许可有效性。

负责人、本店、当前启用账号和登录会话在服务器验证；POST 请求体等候后再次核对身份/门店/安全修订/需改密标志，再进入统一幂等事务。当前员工外部来源在缓存前复核，自己的成功重复请求可回放一次；序列与原修订在实际追加前检查。员工停用仍可保存已核对的历史来源，不启用账号或接收责任。页面来源变化保留填写，重新核对需手工操作，不自动代入和提交。

schema45 新增三表：staff_record_roots/versions/events。固定首版本与新版本的配对事件通过延迟复合外键保证完整原根，原生触发器限制类型事实、连续版本/修订/本店流水、当前负责人身份、规范 UTC、不可更新删除。恢复逐项核对原员工/版本/事件配对、字段未知/实际时间、连续顺序和撤回来源；历史操作者后续改岗位不改原事实。全库202表，恢复数据清单201表加单独核对的schema_migrations；恢复清除登录会话。

七独立虚构阶段：资质未知、人工录入来源、班次、缺勤、培训时间未知、培训已参加、资质新版本后撤回。只追加 demo-staff-record-* 原记录，共7根/8版本/1撤回；保留全部原员工密码、客户、专业、商品、资金与库存。重复初始化不覆盖后续人工变化。

开发核对：22专项；新电脑/手机流程验证未知来源、旧版读取、当前员工来源变更保留输入、明确采用新来源、撤回、手机手工班次、退出隔离及前台无权限。完整910测试、36组浏览器及CLI恢复入口见进度和交接文档。
