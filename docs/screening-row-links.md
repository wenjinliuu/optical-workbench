# 原名单逐行人工客户关联（V0.68）

对应 T08.03 / M17-F01、D、R、A、W6-N1/2、S12。入口：筛查活动 → 本活动原批次与名单 → 固定 CSV 版本 →「人工关联本版原名单行」。只有当前本店准备责任人或门店负责人可读写；责任移交后原员工立即失去原名单、关联及相关客户时间轴权限。家长、外店和非当前责任员工拒绝。

本轮明确采用**已有本店客户**的具体资料版本。员工手工检索姓名或独立客户编号，逐一选择完整资料版本并填写核对依据。单一、多名或没有候选都不自动关联；可以明确选择不是姓名候选的已有客户，但必须留下人工核对依据，名单原姓名和所选原档案各自保留。关联本身不完成正式身份核验、临床同意、专业检查或报告授权，不创建或覆盖客户/联系人/家庭授权、服务周期、到店、预约、权益、资金或库存。

新增关联要求：当前活动有名单处理原说明、未撤回且责任人可用；当前 CSV 版本；该原行没有结构、授权、日期或重复编号错误；手工所选本店客户资料仍为所见最新原版。未知、拒绝、已撤回和错误名单须先明确修订 CSV，再从新版本重新核对。原件与预检错误不改写，原候选仍标为未确认。

关联固定到 `batch_version_id + row_number`，行号使用解析后的名单序号，同时保存完整原文件行号、七列原文本、规范字段及原错误快照。它不是批次根或可变的名单编号关联。CSV 新版本不继承旧版关联；旧版仍可读取其历史、明确撤回，但不能新增关联。有效关联不能直接改指另一客户：先带依据撤回原关联，再手工采用所见客户版本。撤回保留原客户、资料版本及行快照；活动撤回、原授权说明拒绝、责任人不可用或资料后来变更，不阻止当前有权限人员撤回已有错误关联，也不恢复任何权限。

`screening_row_link_versions` 保存连续行修订与本店序列、link/withdraw、原客户资料、采用时活动/批次/资料历史前缀、当时角色、操作人和依据。旧历史不可更新/删除。当前投影及完整分页与准确单版读取分开，后来客户改名不换旧资料，同毫秒后来的版本不能代替原前缀。`src/db.mjs` 注册纯 `screening_csv_row` SQLite 函数，原生插入守卫使用与 API/恢复相同的完整 CSV 解析器核验准确原行，防止伪造行、授权状态或省略原字段；没有该函数的外部 SQLite 连接不能绕过插入守卫。备份和恢复读取不依赖运行会话。

API `/api/screening-row-links/:project/:batchVersion/:row`：

- GET `context` 返回固定原行、当前活动、当前关联与来源；`customers` 明确按姓名/编号检索本店当前资料，完整数量与 1–50 条同来源分页；`authorization` 在采用异步结果前重核权限与来源。
- 根 GET 读取当前关联及历史；`link_version` 准确读取本行某个不可变版本，不跳至最新；历史分页绑定原活动/名单版/行及当前责任。
- 根 POST 仅接受 action、三种明确原来源/活动版本、所见关联修订、手工客户编号/资料版本和依据。withdraw 的客户字段必须为 null，服务端沿用原关联。

新增关联在成功幂等缓存返回前重新检查当前身份、活动原说明、责任、当前 CSV 和客户资料来源；正文等待期间的改岗/改密/会话撤销同样拒绝。修订检查和原行/依据、审计及幂等保存共用事务。来源冲突保留人工依据、清除旧客户选择，须明确重读再手工选择；拒绝权限时清空关联、原名单、编辑器及活动里的嵌套私有内容。退出清空输入，已关闭或过期的迟到响应不能重新出现。

客户时间轴仅展示该客户的原关联/撤回，沿当前活动责任范围过滤，点击返回固定 CSV 原版；从原关联可打开实际已有客户档案。旧客户撤回与新客户重新关联分别落在各自客户历史，资金/到店/预约等记录保持独立。

迁移 059 从 schema58 非空升级，只增加空关联版本表/当前视图和守卫，不制造旧身份关系。恢复核对包含原 CSV 精确行、原资料/活动/批次版本和历史前缀、连续序列、撤回状态/原引用以及当时角色/时间。旧 schema58 备份保持原件，用对应旧版工具独立恢复，再经最新版迁移和重新备份；新恢复工具不静默接受旧结构。

四个独立虚构阶段：待核对、已人工关联、已撤回、撤回后重新关联；新增四份 CSV 原批次、六条关联版本，保留原四份/五版本。重复初始化不覆盖旧客户或后来办理。完整示例共七活动/十一版本、八批次/九版本，schema59/237表（236个恢复数据表）；CLI 新建、重复初始化、全表备份核验、独立恢复与固定投影一致，会话为 0。

验证入口：`npm run check`、`npm test`、`test/screening-row-links.test.mjs`、`npm run test:screening-row-links-browser`、`npm run test:screening-projects-cli`。18 项专项覆盖候选/授权错误、手工选择、旧新版、并发、幂等、原生写入、审计回滚、慢请求撤权、时间轴、非空升级与篡改恢复拒绝；电脑/手机覆盖保留依据与重新选择、关联/撤回/重关联、准确 R1、原客户/名单返回及迟到权限清空。最终全量及双处发布回执以 progress.json / handover.md / progress-sync.json 为准；业务方后期集中验收。
