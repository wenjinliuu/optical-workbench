# 整体业务能力与衔接清单

用户要求按计划逐项执行、统筹各业务能力，暂缓本人体验测试。开发继续进行自动检查和电脑/手机验证；业务方验收保持待完成。本清单用于后续实施衔接，原任务编号和范围仍以progress.json / requirements.json为准。

## 已落地的共同入口（V0.21）

| 能力 | 共用身份 / 历史 | 本轮跨模块约束 |
| --- | --- | --- |
| 客户与家庭 | customer_id、档案版本；联系人独立记录，guardian_links控制查看授权 | 同名/共用电话不合并；联系人变动不自动授权；所有业务关联独立客户 |
| 服务需求 | cycle_id、cycle_versions.version | 类型和客户身份保持，修订需求新增版本；需求草稿与专业计划分别管理 |
| 实际到店 | visit_id、visit_cycles、visit_cycle_versions | 一次到店可接多周期；登记捕获需求版本；后来修订不改旧到店引用；结束到店不结束周期 |
| 资料与附件 | record_id/version、attachment_id；客户与来源范围 | 旧版和附件引用保留；撤销访问不改写历史；通用资料不会自动成为检查/处方/报告 |
| 通用任务协作 | task_id/revision、不可变task_events、固定cycle_id/version及visit_id | 岗位候选/本人认领/接收与执行pending/running/paused独立；转交/退回执行中先暂停，新人接收后主动恢复；到店需求固定；客户/个人/岗位/本店共用任务；异常active/blocked/cancelled独立，取消前阻塞恢复后保留；三视图共用队列 |
| 通用核对依据 | task_conditions.version、task_evidence.version、固定document_version_id及attachment_id | 条件/草稿与执行分别保存；原任务修订与条件版本明确，引用限定同一客户；缺项可保存、只读核对不完成或推进；历史和恢复共同核对 |
| 通用明确完成 | task_completions，原任务修订/条件/依据版本及固定产出 | 当前本人实时核对后明确提交；完成状态独立，全部后续任务写入锁定；已完成筛选/完整统计/八列看板/时间轴/恢复一致；不自动推进专业/资金/权益/库存 |
| 完成更正与显式后续 | task_completion_corrections.version、task_followups及原完成指纹 | 仅追加通用说明；原提交人/负责人，更正不改原产出；负责人/前台显式分派同客户/到店/需求版本，固定采用版本/说明，后来更正不改旧来源；接收/开始独立 |
| 关联任务链与进度 | 已保存task_followups，原客户/到店/需求/产出版本；当前任务责任与状态 | 任意任务定位起始/同级/后续，完整数量与有界分页、岗位/状态筛选、来源/历史及原任务操作；读实际记录，不定义专业自动依赖 |
| 商品目录 | retail_products.id/sku、retail_product_versions.version | 本店负责人维护镜架/镜片/配件/服务，调价停用追加版本；目录启用不等于库存可售 |
| 配镜订单草稿 | retail_orders.id/单号、retail_order_versions.version及固定商品/资料版本 | 负责人/前台录单，多行数量与整数分单价固定；原到店捕获需求保留、客户/来源不改；修订/取消新增完整快照，旧价格/撤销引用历史保留；草稿合计不统计成交或收款 |
| 基础库存与预留 | inventory_events.sequence、inventory_order_events.revision、原order_id/version/position及商品版本 | 可用/预留/隔离独立，服务不建实物账；同SKU需求聚合、全部商品一事务预留，明确释放原行后才改/取消订单；计量单位锁定、不可变流水、客户时间轴及恢复共同核对 |
| 基础收款与误录历史 | payment_events.revision、原order_id/version/明细合计/币种、source_id | 分次手工实收独立登记；有效收款保护原单，负责人误录作废保留来源，真实退款另行办理；外部有效编号并发防重复，门店/岗位查询及时间轴和恢复核对 |
| 订货与加工 | processing_jobs原order_id/version/position、processing_events.revision与完整不可变快照 | 明确逐行供货/加工/责任人/交期；分批数量completed≤started≤received≤原单数量，执行后安排锁，延期并行；活动工单保护原单，stock备料锁预留；完成待质检、资金独立 |
| 质检、返工与分项签收 | fulfillment_events连续revision、固定job_id/processing_revision/position与原不合格/返工/合格批次source_id | 明确项目结论，初检及子批容量守恒；返工分派/开始/完成/复检独立，只有合格来源可签收；款项/库存出库分别核对，历史/时间轴/恢复保留 |
| 签收批次实际出库 | inventory_outbounds.outbound_revision、库存basis_sequence及原delivery_id/order_id/version/position | 原预留优先扣减，否则可用实物；分批容量与配对版本，原分配快照保持、当前数量独立投影；已出库原单停止整单预留/释放 |
| 原单售后与退回隔离 | aftercare_cases原delivery_id、aftercare_events.revision及退回dispatch_id | 一个活动案例、固定原客户/行/版本，分派与本人执行状态独立；退回原出库全局容量及案例量核对，隔离独立保管，结束/取消不转可售或退款 |
| 员工协作权限 | user_id、store_id、岗位动作、有效会话 | 改岗/停用/改密即时撤销；首次改密门禁；跨店与家长内部资料读取拒绝 |
| 总览与时间轴 | 已保存原记录及受限审计投影 | 周期需求、到店引用、资料、家庭状态可核对；早期缺失明确未知，不补造历史 |
| 一致性与恢复 | 幂等键+动作+身份、同库事务、审计、快照/恢复回执 | 新增表/版本必须进入备份和恢复校验；失败业务/版本/引用/审计同事务回滚 |
