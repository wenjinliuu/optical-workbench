# 整体业务能力与衔接清单

用户要求按计划逐项执行、统筹各业务能力，暂缓本人体验测试。开发继续进行自动检查和电脑/手机验证；业务方验收保持待完成。本清单用于后续实施衔接，原任务编号和范围仍以progress.json / requirements.json为准。

## 已落地的共同入口（V0.9）

| 能力 | 共用身份 / 历史 | 本轮跨模块约束 |
| --- | --- | --- |
| 客户与家庭 | customer_id、档案版本；联系人独立记录，guardian_links控制查看授权 | 同名/共用电话不合并；联系人变动不自动授权；所有业务关联独立客户 |
| 服务需求 | cycle_id、cycle_versions.version | 类型和客户身份保持，修订需求新增版本；需求草稿与专业计划分别管理 |
| 实际到店 | visit_id、visit_cycles、visit_cycle_versions | 一次到店可接多周期；登记捕获需求版本；后来修订不改旧到店引用；结束到店不结束周期 |
| 资料与附件 | record_id/version、attachment_id；客户与来源范围 | 旧版和附件引用保留；撤销访问不改写历史；通用资料不会自动成为检查/处方/报告 |
| 通用任务协作 | task_id/revision、不可变task_events、固定cycle_id/version及visit_id | 分派/本人接收/转交与执行pending独立；到店任务沿用旧需求；换班重新接收；人员停用显式转交；客户/个人/本店视图共用任务 |
| 员工协作权限 | user_id、store_id、岗位动作、有效会话 | 改岗/停用/改密即时撤销；首次改密门禁；跨店与家长内部资料读取拒绝 |
| 总览与时间轴 | 已保存原记录及受限审计投影 | 周期需求、到店引用、资料、家庭状态可核对；早期缺失明确未知，不补造历史 |
| 一致性与恢复 | 幂等键+动作+身份、同库事务、审计、快照/恢复回执 | 新增表/版本必须进入备份和恢复校验；失败业务/版本/引用/审计同事务回滚 |
