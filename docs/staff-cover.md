# V0.51 原休假任务交接安排

T07.03 的本店负责人入口。固定原员工和原休假/缺勤记录，手工选择1至30项当前原通用任务修订、逐项拟接收员工及覆盖说明。人员安排与实际任务责任分别保存，原专业/加工/同意等13类当前责任沿已有入口逐项核对。正式专业核验、人事政策、容量、多店代办和整体验收仍待后续；下一T07.04开始已保存收款退款事实核对。

保存安排不转交任务。拟接收人须本店当前启用、已改初始密码、区别于原员工；岗位不代表专业资质。原任务的实际转交继续使用原tasks接口和手工选择接收人的原表单，原执行暂停后等待新人接收，阻塞原因保留。每项各自核对原任务修订与当前责任；一项已转交后，其他未变原项仍可办理。专业流程不从本安排批量自动采用。

每版固定原休假版本/事件、保存时原员工及逐项拟接收人资料快照、原task_events(task_id,revision)、完整逐项覆盖说明、原来源引用/说明、依据和下一步。快照是保存时实际读取的账号资料，不补历史资格/许可。新版本手工采用当前来源；原安排和旧人物名称保留。撤回仅追加解释，不撤销实际任务转交，后续可明确新版本。员工安排没有独立客户归属，不新增客户时间线；实际原任务交接保留原客户及原时间线。

GET /api/staff-cover/absence/:id 为完整安排列表，/source 为原员工当前通用任务与13类责任总数，/candidates 为本店符合账号条件的拟接收员工（可按q文字筛选）。默认30项、最多100，完整总数和来源凭据，后续页必须expected_source。GET /api/staff-cover/:id 支持固定旧version，以及事件limit/offset/expected_source。读取旧安排不要求原休假仍有效，当前员工、原任务或来源改变会如实标记。

POST /api/staff-cover 新建，/:id/versions 追加人工安排，/:id/events action=withdraw。共同字段expected_sequence/reason/next_step；原安排追加须expected_revision/expected_version，新建带absence_id。正向记录另带expected_external/title/source_reference/source_note/items；逐项严格task_id/task_revision/recipient_id/expected_recipient_source/coverage_note。重复原任务拒绝，原任务须当前原员工且未取消/完成；没有实际日期匹配/自动审批推定。

POST等待请求体后核对当前负责人、门店、启用、安全修订/需改密及会话。正向外部原员工/休假与拟接收人来源在缓存前复核，成功自己的重复请求只回放一份旧事实；实际新增前检查安排流水、原版本/修订、原任务当前责任。负向撤回可在原休假来源后来变化后追加，不伪造当前来源。页面变化保留手工填写；手工重新核对后仍需明确保存，不自动提交或替代接收人。

schema46四表staff_cover_roots/versions/items/events，通过延迟复合外键保证完整原根/版本/配对事件，原任务事件采用复合外键。原生连续编号、版本/修订/本店流水、完整逐项、当前演员/账号快照、规范UTC、文本及不可更新删除。捕获原任务事件/完成、原休假流水前缀区分同毫秒前后；独立恢复核对固定原休假、原责任、人物快照与原配对，后来账号停用/改岗位不覆盖旧事实。全库206表，恢复清单205表加单独schema_migrations结构核对；恢复会话清零。

八独立虚构阶段：待办理两项、正在执行、原阻塞、拟接收人后来停用、原休假后来改变、明确撤回、手工新版、原任务实际转交仍待新人接收。只追加demo-staff-cover-*自己的任务/休假/员工及安排，不覆盖此前任务/密码/资金库存；8安排/9版本/1撤回/9原任务，重复不会重置后续手工变化。
