# V0.59 原预约请假、调课意向与实际办理

继续 T08.02，保留全部 V1.1 原任务、需求和整体验收状态。本人从已经明确公开给自己的实际预约选择当次请假，或明确选择同客户、同原计划版本的已开放目标时段。正式预约调课必须另选时段；候补可以选择原时段提出调整/转正意向。原安排、公开版本、原计划和目标版本固定，提交不占名额，不批准请假、不改变原预约。

员工在原申请详情独立选择实际 leave、move 或 promote，核对当前授权、原公开及意向、原预约修订、计划与资源、容量和重复/时间冲突。请假沿原负向动作办理，不要求已暂停的计划继续有效。调课沿原预约状态办理，候补调课仍是候补；候补转正必须明确选择原时段 promote，满额拒绝。每次只修改这个客户原预约的一个事件，客户、周期、原计划版本和预约编号保持。

办理必须同时明确原排期说明、内部依据和向本人公开的实际结果。实际事件与独立结果公开、不可变关联、审计和幂等结果同事务保存，任何一步失败全部回滚。原公开根/版本不覆盖，家长在原变更意向中读取最小实际结果；内部依据、员工/资源身份及其他客户资料不进入家庭响应。没有消息送达、扣次、退款、补课或实际到店推断。

同一本人、同原预约只允许一个未撤回/未结束/未实际办理的变更意向，跨公开根也不能重复。提交内容不能修改；本人明确撤回后可重新提交。实际来源变化保留旧意向，不能借刷新自动采用新预约。新来源必须重新明确公开并提交新的意向。实际办理后保持历史；同键重试只返回第一次结果，但撤权、原公开撤回/换版或原意向撤回/结束阻止正向缓存重放。

## API 与页面

- 本人 GET `/api/family-changes/publications/:publication/options`：同本人/客户/原计划版本的目标开放时段，仅最小公开内容，默认 30、最大 100，后页带同来源 `expected_source`。
- 本人 GET `/publications/:publication/context?kind=leave|move&offer_id=`：明确选择的原安排/新目标和来源令牌；带 `expected_source` 可在采用响应前复核。请假不接受目标，调课必须明确目标，不预选。
- 本人 POST `/publications/:publication/request`：明确种类、目标（请假为 null）、标题/本人说明及来源令牌。意向和固定关联原子保存。
- 本人/员工 GET `/requests/:request`：当前范围的原变更记录；普通有效申请没有变更关联时返回 `record:null`。本人读取最小字段，员工读取原引用与各实际动作的守卫。
- 本人 GET `/requests/:request/authorization?expected_source=`：采用内容前重新核对授权及公开结果；迟到响应不重新显示。退出登录清空新增弹窗。
- 员工 POST `/requests/:request/execute`：明确实际动作、当前来源、排期说明、内部依据和对外结果。来源或容量改变要求明确重新核对；重新读取保留输入。本人不能执行，专业人员及其他门店不能读取内部意向。

正文等待后重查当前角色、门店、安全修订及强制改密，共享事务重查会话；当前授权/撤回保护在幂等缓存之前执行。未知/重复查询参数、假审批或未知字段拒绝。家长入口在原公开预约卡片；员工入口在原变更申请详情。所有选择器初始空白。
