# 质检、返工与分项签收 · V0.20

T04.04的本地开发切片，从真实保存的加工工单接续。质检项目由操作人逐项填写，不预设未知的专业标准或合格阈值；本地岗位并不证明正式资质。原50任务/287需求与依赖保持，业务整体验收待用户后期集中体验。

## 数量与固定来源

每条记录固定job_id、processing_revision、原position及本次数量，原客户/门店/订单/商品版本由工单引用。只有当时已保存的completed数量可进入初次质检。每行独立计量，不合并片、副、个，也不合并重复商品行。

check_pass/check_fail保存1–20个明确项目，每项label/result/notes；result必须明确为pass或fail。合格批次所有列出的项目合格，不合格批次至少一项fail。批次数量不能超过未初检加工完成数量。这里保存实际填写的项目，未保证覆盖正式专业质检清单。

不合格批次经rework_assign明确分派本店有效责任人和返工说明；rework_start独立开始，rework_complete独立完成。完成返工仍须以该完成批次作为source_id再次check_pass/check_fail；再次失败可重复返工。返工安排不自动开始，完成返工不自动通过质检，也不改变原加工数量、供货安排或专业参数。

| 动作 | 必须固定的source_id | 后续数量 |
| --- | --- | --- |
| 初次check_pass/check_fail | null（固定加工记录版本） | 原行completed减此前全部初检数量 |
| 复检check_pass/check_fail | rework_complete | 此返工完成数量减此前全部复检数量 |
| rework_assign | check_fail | 此不合格数量减此前全部返工安排 |
| rework_start | rework_assign | 此安排数量减此前全部开工 |
| rework_complete | rework_start | 此开工数量减此前全部完成 |
| deliver | check_pass | 此合格数量减此前全部签收 |

所有来源属于同工单、同原行，子批次总量不超过父批次。逐行投影为未初检、合格待签收、不合格待安排、返工待开始、返工中、待复检、已签收；七类之和等于原加工completed。失败→安排→开始→完成→复检逐项移动，原记录不改写。全部签收要求每行delivered=原quantity，尚未加工完成和未签收项保留。

## 签收与跨模块边界

负责人/前台从合格批次明确保存本次数量、实际领取人、规范UTC交付时间和签收/调整说明。不能从不合格或未复检来源签收，超量和重复来源消耗拒绝。领取人是实际记录的姓名文本，不自动授予家长账号权限，不声称完成监护证明核验或电子签名。

款项独立核对，本版未设置未确认的尾款门禁、欠款/应收或真实退款规则。stock分项签收时原单库存预留必须仍有效；签收记录不自动作为库存出库流水，原库存占用继续保留并禁止释放，待下一切片接实际出库/未交付项/损耗/售后。purchase到货/签收也不补造库存入库或出库。本版页面明确显示签收记录与库存出库分别核对，全部已签收不等于完整库存/资金结算。

已保存的加工/质检/返工和签收记录均不可改删；误录后的业务更正、报损、取消返工、退货/售后及专业参数变更影响确认需独立衔接。未接外部取镜通知、供应商返修、正式质检模板和附件签收证明，不把缺失规则设为默认批准。

## 权限与接口

本店三类员工可读；负责人/专业人员明确质检，负责人/前台安排返工和登记签收。返工开始/完成限本次返工固定责任人或负责人；另一个专业人员不能代执行。停用、改岗/撤销会话和首次改密即时门禁；可给待首次改密人员安排，但其业务执行先改密。跨店404，家长拒绝内部接口/时间轴。

- GET /api/fulfillment/jobs?q=&state=&limit=50&offset=0：已存在加工完成数量的未取消工单；字面检索工单/客户/标题，state为all/pending_review/rework/ready/partial/delivered；完整计数，有界分页最多100条。
- GET /api/processing/jobs/:id/fulfillment?limit=50&offset=0：固定原单/当前加工版本、逐行七类数量、可处理来源批次及独立历史分页。历史回执保留原processing_revision、source_id/source_revision、项目、原责任人、签收人与时间；不使用当前版本替代旧记录。
- POST /api/processing/jobs/:id/fulfillment/events：expected_revision、expected_processing_revision、position、quantity、action、source_id、reason；检查需checks；安排需assignee_id/instructions；签收需receiver_name/receipt_note/handed_at。其他字段严格拒绝。

数量为1–999整数；依据最多300字，项目名/领取人最多120字，项目记录/返工说明/签收说明最多1000字；实际交付时间为2000年之后且不晚于登记的规范UTC ISO时间。会话、改密/岗位、门店、CSRF及当前加工/质检版本在同事务内核对；FULFILLMENT_CONFLICT须明确重读，FULFILLMENT_STATE拒绝来源/数量/质检结论。审计、业务和幂等同成败，同意图重试返回原结果，不同意图复用同键409。
