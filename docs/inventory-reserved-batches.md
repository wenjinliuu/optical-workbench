# 实际原单预留出库的原批与交付客户 · V0.48

实际销售出库可明确选择固定原预留行内的当前人工原件观察，完整对应本次交出数量。出库仍由原实际库存流水扣一次 reserved；原批引用只保存来源，不另预留、扣库、付款或生成仓位分配。可用观察和原单预留观察使用各自固定来源，不能借用；未选择时保留“原批来源未记录”，旧出库不补造批次。

每次选择固定原观察根、不可变版本和当前事件，填写实际交出数量、原件来源引用、说明及本次整体事实来源。所有原批数量之和须等于本次实际出库数量，最多30个来源，同一根只选一次。原收货SKU/单位/类别、原预留事件与订单行、仍有效的预留、原资料版本、库存/已出库/实际退供/质量前缀和观察状态分别核对。原收货已明确售出的数量、实际退供和原质量保护共同限制后续来源，另一箱同款数量不能替代已售原件。

实际出库后须重新现场观察才能选剩余来源，不按出库数字自动生成新观察。其他商品的出库不使这批原件观察失效；请求的完整序列仍用于防止选取期间发生变化。当前原批可用余额未记录，不把观察和累计交付量推算为仓库今日余额或独占分配。

- GET `/api/inventory/reservations/:id/lines/:position/batch-sources`：固定原预留行的当前实际原件候选、完整总数、默认30/最大100，后续页须 `expected_source`。
- 原 POST `/api/fulfillment/events/:id/dispatch`：可选 `reserved_batch_sources`（`custody_id/custody_version_id/custody_event_id/quantity/source_reference/note`）、`reserved_batch_source_note`、`expected_reserved_batch_sequence`、`expected_reserved_custody_sequence`。不能同时提交可用 `batch_sources`。
- 原 GET `/api/inventory/outbounds/:id/batches`：只读本次实际固定原批，明确 `source_mode`、原收货与观察版本。
- 原 GET `/api/purchase-receipts/:id/delivered-batches`：合并已明确的可用及预留实际交付，最小客户/原单版本/原行/原观察与数量；后续页同时采用 `expected_sequence` 和 `expected_reserved_sequence`，不以当前客户资料改写原单来源。

本店接待/负责人办理实际出库，专业人员只读，家长及跨店拒绝。正文等待后核对实时角色、门店、有效状态和重置密码。实际负事实成功幂等重试返回同一原事实，即使后来解释撤回或资料更正；当前身份和原专业/签收来源保护仍核对。审计失败时实际扣减、原批声明/引用、上下文和重试缓存一起回滚。

schema44新增9表，总199表：预留实际原批声明/引用，以及可用观察、预留观察、质量根、可用实际原批声明、原收货、质量事实、实际出库的互相前缀。原schema43出库捕获 `legacy=1` 的空新账技术前缀，不允许补入新预留声明。两个实际销售来源序列分别保留，历史容量按当时双前缀重算；同毫秒先后通过互相上下文核对，不用今日总数改写旧观察。备份/独立恢复保留全部199表并撤销会话。

原出库页明确选择、空白实际输入，旧来源变化时保留填写并阻止保存。原批客户追溯能打开原订单和准确数字观察版本，即使后来已有V2仍显示原V1。手机及退出后的迟到响应使用原身份和页面上下文隔离。
