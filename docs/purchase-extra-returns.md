# V0.44 超收未匹配原件的分批退回与供应方收件

原收货的实际数量减明确匹配原采购数量，是原超收未入账数量。它不等于今天实际保管量，不属于已匹配商品库存；绑定原采购的部分继续原验收/入库/原批质量退供流程。

负责人明确记录原收货、供应方、固定商品版本及单位、真实超收原件身份数量与保管核对时间/来源，再独立安排商业退回。草稿、提交、批准和驳回不表示实际交出或退款。多个有效安排共享原超收余量，不能重复安排；取消未交出安排、部分交出后停止剩余安排保留各自旧版本和实际事实。

实际分批交出引用当时原明确商业批准和固定收货来源。数量不超过本安排未交出量及原超收尚未交出量；时间不早于批准，不晚于录入。供应方分批实际收件引用原交出批次、数量不超过该批尚未收件量，时间不早于交出。两类实际事实均不写SKU库存、销售出库、隔离退供或资金流水。不推定供应方责任、商业费用或退款。

商业提交/批准须当前明确采用的原收货资料。后来原资料修订，可重开尚未交出的安排并明确追加采用新版；原已批准后的实际交出保留原批准引用，不被后来供应方停用/商品改名或资料更正抹去。任何实际超收交出后，原收货不能取消为“未发生”；尚未交出但有有效安排须先明确取消安排。部分停止不取消原实际到货或交出。

未知外部编号、联系资料、批号效期仓位保持未知。人工实际来源必填；已知来源唯一标识分别限定原安排交出/原交出收件，独立外部编号可重复，未知标识不伪造外部去重。原收货数量减已交出只是未退回账面预算；今天真实保管量仍未知。

## 入口和权限

从原采购的收货详情选择“超收未匹配数量退回与收件”。负责人办理商业安排和实际交出，负责人/前台转录供应方实际收件；专业人员只读，不赋予仓库质量资质。当前门店/权限、密码重置及会话在请求体读取后再次校验，家长及跨店拒绝。

读取 `/api/purchase-receipts/:id/extra-returns` 的原来源及安排；POST `/api/purchase-extra-returns` 新建，GET `/:id` 查看完整来源及历史，POST `/:id/versions` 追加安排版本、`/:id/events` 明确商业动作、`/:id/handoffs` 记录实际交出。GET/POST `/api/purchase-extra-handoffs/:id/receipts` 分别读取/登记原交出批次的供应方收件。

默认30条、最多100条，完整计数与后续游标分开。后续页须 expected_sequence 保持当前门店超收共同序列；指定安排版本为数值 version。商业写入检查原安排修订/版本及共同序列，安排新增/采用还固定原收货版本和收货序列，交出固定原收货退回修订及本安排已交出量。来源变化409保留填写，不能自动替换原依据；退出清空异步对话框和填写。

## 数据、原生保护和恢复

schema40追加六表：purchase_extra_return_plans、versions、events、handoffs、receipts，以及purchase_receipt_extra_return_context。原生触发器限定原来源、当前实际权限/时间、商业转换、共享容量、固定批准、实际数量、已知来源唯一性和不可变记录；事务/SAVEPOINT将原根、版本、事件、实际事实、审计和重试缓存一起回滚。

原收货事件捕获当时超收共同序列，商业安排捕获当时收货共同序列；同毫秒也能核对采用先后，旧schema39升级只为旧收货补空新账的技术零前缀，不补造过去的退回事实或今天保管量。恢复重放商业容量及分批交出/收件，验证六表配对、原固定单位、完整时间序列、同刻前缀和原收货取消保护。CLI独立恢复核对165表，并清空会话。

七种独立虚构阶段：草稿、已批准未交出、部分交出待收件、全部交出待收件、分批已收、部分停止、驳回。各有自己的原采购和收货，已匹配1件与超收3件分开；追加与重复演示不修改旧业务行、库存或资金。20项专项及电脑/手机检查覆盖商业、实际、恢复、旧schema、并发、正文期间身份/来源变化等。

原T07.01/T07.02及W5部分需求仍为局部实现，完整仓位/批次分配、扫码、盘点调拨、成本、正式仓库身份、政策与业务验收待后续。主应用继续本地开发。
