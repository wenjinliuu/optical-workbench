# 本地备份、核对与恢复

V0.20 技术演练流程；正式保留期限、异地存储、恢复目标和生产权限仍待确认。

## 生成与校验

```sh
npm run backup
```

来源由 DATABASE_PATH 指定（默认 data/workbench.sqlite），目录由 BACKUP_DIRECTORY 指定（默认 backups）。来源必须已存在；工具只读打开来源，不创建空库、不在备份时迁移原库。VACUUM INTO 生成一致快照，文件名使用时间与 UUID；不会覆盖旧备份。输出包含 backup 与 manifest 的实际路径。

备份旁的 .sqlite.json 清单记录格式、应用版本、创建时间、大小、SHA-256、数据库结构指纹、迁移列表和基础表数量。快照需通过 integrity_check、foreign_key_check、预期结构/历史保护触发器、附件内容哈希/长度及元信息核对，才保存清单。文件和清单权限为0600，首次创建目录0700。不输出资料内容、密码或会话令牌。

以下路径为示例，替换为上一步输出的实际 backup 路径：

```sh
npm run backup:verify -- backups/workbench-示例.sqlite
```

校验拒绝损坏、缺少/不匹配的清单、关联错误、附件不一致或其他版本结构。SHA-256清单用于核对损坏，不是数字签名；使用可信的本地备份来源。旧版没有清单的快照不能直接通过此工具；使用匹配版本的工具或按旧版流程在副本上核对，不修改原快照。

## 在独立目录恢复

```sh
npm run restore -- backups/workbench-示例.sqlite data/restored-example
```

目标目录必须尚不存在，父目录需存在；已有目录、现有数据库及WAL/SHM文件都拒绝覆盖。工具先校验备份，复制后再核对指纹，再在恢复副本中撤销全部会话；其他基础表数量必须与备份一致。密码、停用状态、家长关系、资料版本、附件、审计和业务防重复记录保持快照状态。

成功输出恢复库路径及 restore-receipt.json。回执包含备份指纹、恢复文件指纹、撤销会话数及核对结果。没有成功回执的中断目录不用于启动；先独立检查。恢复文件和回执权限0600。

## 切换与核对

保留当前运行库，停止原服务，再使用新 DATABASE_PATH 启动：

```sh
DATABASE_PATH=data/restored-example/workbench.sqlite npm start
```

重新登录；旧cookie必须失败。核对授权客户、旧资料版本、附件内容、人员停用/待改密状态及原审计。授权和密码是备份时的状态，启用前核对快照之后的授权变更。原库与原快照保留，可停止新服务再指回原库；不合并两边的新写入。

所有工具拒绝 NODE_ENV=production。本轮没有资金、权益和库存账；基础表恢复成功不代表完整业务对账或生产RPO/RTO通过。

## 故障定位

每个HTTP响应带服务端生成的 X-Request-Id，错误JSON附 request_id；浏览器错误提示显示同一编号。服务端故障日志只记录编号、时间、方法、路由模板、状态、错误码、耗时和当前已登录门店，不记录查询、请求体、密码、cookie、CSRF、客户编号、SQL或异常堆栈。

负责人在“运行与恢复”查看本店已登录请求：本次启动累计数、4xx/5xx/中断数、最近200个请求的P95耗时、该窗口内最近20条故障。重启计数清零；未登录失败只进入服务端日志，不分发到门店页面。当前为本地观察值，不是性能目标或持久监控承诺；日志存储、报警、轮转与规模验证待正式运行方案。

## V0.29 训练资源与排期
