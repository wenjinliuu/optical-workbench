# 套餐规则记录与独立权益账 · V0.28

本轮对应T05.02的独立技术部分，原任务依赖和整体验收保留。保存明确购买/赠送来源、次数或人工期间、登记采用的规则版本及误录反向流水。权益登记、专业计划/课程、预约和资金独立，技术暂留量不是实际可用权益或财务余额。

## 入口和权限

“套餐与权益”查询本店目录、权益账和匹配总数，按客户/套餐名称/编号/权益类型筛选并分页。从客户档案可进入当前客户的权益账，再明确登记该客户的新来源。负责人维护目录规则版本；负责人/前台登记原购买或赠送；仅负责人纠正原流水误录。完整流水、来源条目、资料附件和购买说明只对负责人/前台开放，本店专业员工只读取不含凭据/完整流水的数量摘要。家长没有内部权益入口。

账户保存客户、训练需求版本、可选个人计划及其版本。计划状态、调整/结束不改变权益，权益也不确认专业计划。无计划时须采用当前训练需求；明确关联计划时采用它固定的原需求和明确计划版本，可以追溯旧计划。资金或权益误录纠正不结束周期。

## 套餐和规则记录

目录以编号定位，规则记录各版保存名称、按次数或按期间、目录启用/停用、明确服务范围、来源说明与操作依据。七项购买、赠送、效期、扣次、冻结/延期、冲销、退款分摊说明可留null=待明确规则，没有默认次数、效期或公式。目录启用只允许新账采用，不代表正式条款或资质已确认。

新账必须采用本店当前启用的规则版本。之后的规则修订、类型变化或停用不覆盖旧账；旧账后续来源继续按原版登记。修改真实规则应新版本/新账，不能把旧权益转换为另一类型。固定的是登记采用的规则记录，未知的实际原购买条款不重建，正式购买/销售合同规则仍待确认。

## 原购买/赠送与误录冲销

每次grant明确paid或gift。按次数须明确1–1,000,000整数次；按期间quantity=null，须明确合法起止日期。次数可选完整起止日期，也可两者均未知；仅填一端、无效闰日或结束早于开始拒绝。日期仅记录已知期间，不自动激活、失效、扣次或冻结，跨来源期间可以分别登记，不由天数推算次数。

原来源条目编号和说明、已发生购买/赠送UTC、登记说明与依据必填。可固定当前客户的原资料版本及可访问附件，后来资料变更不覆盖来源。需要实际发生时间，不能用计划日期冒充购买/赠送；本轮没有到账核验或销售订单生成。来源条目可按购买单号+明细识别，每个明确条目独立登记；同客户、同来源类型、同条目仍有未冲销权益时不能再次登记到其他账，避免重复记账。全部误录冲销后可以明确重新登记，旧流水保留。

reverse只能引用本账原grant。次数可部分或全量纠正，所有反向流水累计不能超过原明确次数；期间整条纠正，不能修改原日期或次数。反向流水固定原购买/赠送、原条目/说明、资料附件和发生时间，新纠正依据/登记人/时间另外保存。原附件后来撤销仍能纠正原误录，但新grant不能采用已撤销附件。原记录和反向记录均不可覆盖/删除。

冲销只更正权益登记，不生成现金退款，不代表已经退款，不计算已用、付费/赠送分摊或优惠。按次数分别显示购买/赠送累计登记、已冲销、按记录暂留次数；按期间显示登记/已冲销/暂留的期间条数，不把期间条数当课次。实际可用、临床适用、扣次和效期继续待R03明确。

## 接口与并发

同源/api，所有写入要求当前会话、X-CSRF-Token和Idempotency-Key，未知字段严格拒绝。

| 路径 | 作用与固定输入 |
| --- | --- |
| GET/POST /entitlements/packages | 查询本店目录；负责人创建规则记录 |
| GET /entitlements/packages/:id?version=&limit=&offset= | 当前/固定旧版及分页历史 |
| POST /entitlements/packages/:id/versions | expected_version及完整新规则记录 |
| GET /entitlements/accounts 或 /customers/:id/entitlements | 本店/客户账查询，q/kind/limit/offset及完整匹配数 |
| GET /entitlements/customers/:id/options | 当前启用规则、训练需求、当前计划、资料附件各最多100项，截断提示；account_count、customer_sequence |
| POST /customers/:id/entitlements | 固定package_id/version、cycle_id/version、plan_id/version（可同时null）、expected_account_count、expected_customer_sequence、grant；建账与原grant一事务 |
| GET /entitlements/accounts/:id | 固定规则、原来源、当前revision/customer_sequence、独立购买赠送汇总、分页历史 |
| POST /entitlements/accounts/:id/events | action=grant或reverse、expected_revision、expected_customer_sequence及本次明确字段 |
| GET /entitlements/events/:id | 原事件及它的当前尚未冲销量，用于定位和明确纠正 |
| GET /customers/:id/entitlement-summary | 本店员工只读技术数量；不含条目凭据、完整流水、附件/资料编号和购买说明 |

原grant字段：origin、quantity、valid_start/end、basis_reference/note、document_version_id、attachment_id、occurred_at、note、reason；period的quantity须null，未知引用和次数型未知期间均null。reverse仅填写source_event_id、quantity（次数正整数/期间null）、note、reason；其余原来源由服务端复制，不允许伪造另一个购买/赠送身份。

客户连续sequence覆盖该客户所有账；账内revision和客户sequence一起校验，别的账发生购买/赠送或冲销后，旧预览需明确重读。目录修订校验原version；建账校验客户账数和客户sequence。相同身份/动作/键/完整内容重放原结果，修改内容不能复用已有成功的键。业务根、规则、流水、审计和幂等同事务失败回滚，处理中撤销/停用/强制改密再次检查；冲突重读保留数量、原规则选择、资料、UTC、来源和依据，由用户明确核对后再保存。

## 原生约束与恢复

schema25的四表entitlement_packages、entitlement_package_versions、entitlement_accounts、entitlement_events均不可修改删除。复合外键及写入触发器核对本店/客户、固定原需求/计划、启用规则、当前有效人员、连续序号、数量/合法日期、原grant引用与来源复制、重复原条目和冲销容量。单账每种来源累计登记次数技术容量1,000,000,000，防止数值失真，不是门店套餐规则。

套餐每次规则版本捕获当时本店建账serial；账固定采用版本与建账serial交叉核对，同一毫秒新规则不倒灌旧账。客户事件sequence给跨账纠正/重新登记定义连续先后，账根捕获创建前客户sequence，初始grant与根同时间/人。恢复完整回放版本、固定来源和原流水容量，拒绝改动未来规则、重复条目和过量冲销，恢复副本会话清零。历史岗位可能之后改变，恢复保留固定历史而不以当前角色改写过去；新写入仍校验当前角色。附件旧撤销表只有时间戳，同毫秒历史撤销不重建未知顺序。

schema24非空升级只新增空四表，不补造购买、赠送、消费、规则确认或余额。权益事件进入资金权限范围内的客户时间轴，可定位原账和原grant；其他业务与专业课程保持。
