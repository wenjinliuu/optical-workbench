## 阶段定义

第一阶段正式出口为 P00 + P01。P00 尚缺门店实表、规则决定与正式架构确认，P01 已补授权附件与通用资料快照，仍缺正式身份/组织与资质职责、专业业务与审批衔接、完整运行恢复和正式发布。当前代码是独立的本地基础验证切片，不代表依赖链已批准，也不领取后续正式任务的完整验收。

## 开发推进顺序

1. 业务负责人确认 rules.md 中影响下一切片的门店规则；其他未知项继续保留阻塞。
2. 确认正式部署、数据存储、员工身份、家长身份和恢复目标，将 architecture.md 的暂定项变为有依据的决定。
3. 完成 P01 的组织、附件授权、不可变业务版本与运行保障，并逐项留下验收证据。
4. 通过 P00/P01 后正式推进 P02：家庭关联 → 周期和到店 → 检查草稿/确认/修订 → 处方/报告发布。
5. 再进入 P03 岗位任务和交接；P04/P05 扣次和退款实现始终依赖明确公式。

全部 50 个任务与 287 条需求保存在 progress.json / requirements.json，需求实现与业务验收分列。局部自动测试通过不代表整个需求或阶段验收。

## 本轮验收目标

从干净环境运行 npm ci、npm run demo、npm start；通过账号登录，创建客户、看到重复提示，创建两个独立周期草稿，退出后重新登录仍能读取；负责人看到相关审计。跨店、越动作、越家庭请求被服务端拒绝。重复请求只保存一份，业务写入和审计失败一起回滚。手机宽度页面能操作，键盘能访问表单与对话框。

本轮使用纯虚构资料，不向蓝图站点写入真实客户数据，不改变蓝图发布版本。发布版进度目前仍是原快照；本仓库是本轮实际开发进度的来源。蓝图进度同步安排在独立文档发布任务中。
