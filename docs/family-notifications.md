# 工作台内服务通知与主动已读（V0.61）

对应T08.02 / M16-F04。负责人/前台明确指定当前有效授权本人，填写对外标题/内容与单独内部依据，发布服务通知。没有自动业务触发、短信、邮件或微信发送；原通知偏好和同意说明分别保存，通知不改变临床同意或预约。下一步接原本人申请/回复的固定业务来源与原入口追溯。

每份通知独立，公开新版或撤回追加不可变版本。本人只读当前仍公开的通知及撤回界限之后的原版本；重新发布不恢复撤回版本。员工保留完整历史。读取列表、详情或历史都是只读，不生成送达或已读。

本人主动选择“标记这版已读”才保存原版本的唯一回执。旧版已读不改变新版未读，也不会被挪到新版；再次标记同一版本保留原回执且不追加第二份业务审计。显示“本人主动已读”的时间来自这一次明确操作，不代表外部送达、身份核验、专业签署或同意批准。当前版本完整未读数量和全部/已读/未读筛选一致，有界分页同时绑定原筛选、根通知与来源。

`/api/family-notifications/family|staff/:customer/:recipient` 为指定本人列表。员工POST新通知，`/:root` POST明确公开新版或撤回，GET读取原历史；家庭POST `/:root/read/:version` 主动标记原版已读。`/authorization?expected_source=:adoption_source` 在采用异步响应前复核当前授权/内容/回执。GET分页使用返回的source_token，它另外绑定筛选和原根；写入使用adoption_source固定当前事实。员工选取本人共用已有家庭通知/同意context入口，包括失效授权后的原历史。

服务端检查本店/本人/当前有效授权、活动账号/会话/待改密，正文等待后重新核对。所有写入与审计/幂等在同一事务，说明撤回或授权撤销拒绝旧回执缓存重放。原生连续版本/序列/身份/时间及不可覆盖保护与恢复检查一致；回执保存当时通知序列前缀，恢复能区分同刻已读与后来撤回。新通知和已读加入客户内部时间轴，仅负责人/前台可读。

桌面与手机保持同一事实。员工空白明确填写，来源变化拒绝旧提交、保留填写并提供手工重核对；家长新读取采用前复核，迟到撤权内容清空，退出清空对话框。
