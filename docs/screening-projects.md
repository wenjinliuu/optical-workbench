# 筛查活动与名单准备原说明（V0.66）

对应T08.03 / M17-D、R、A、W6-N1等。本店保存原机构、活动标题/范围、明确准备责任人和名单处理授权原说明；未知引用须为空，有原说明/拒绝须明确原引用和说明。这里只保存准备事实，不代表正式授权核验、监护身份或临床同意，不授予专业检查、个人报告或机构汇总权限。

同一个活动保留不可变版本、连续修订/门店序列、原操作人和保存时间。撤回另记版本并复制原机构/范围/责任和授权原说明，只追加撤回依据；它撤回本准备说明，不补造法律上的授权撤销。之后重新记录必须提交明确新字段，不恢复旧许可。当前无原批次/名单存储或自动关联。

本地`screening:prepare`开发岗位限本店。普通员工只能明确创建自己负责的活动，当前责任人可追加自己的说明；负责人可明确指定和移交准备责任。正向记录要求当前本店可用准备员工，失效责任保留在旧历史，负责人可明确撤回或另选可用责任人。准备岗位不等于正式专业资质，经理不能通过本记录获得专业批准权。

`GET /api/screening-projects` 共用全部/准备记录/撤回筛选与完整数量、有界分页；`/:root` 读本原活动和同源历史。`/context` 给当前可选员工及原来源；`/authorization?expected_source=` 采用迟到读取前再次核对。来源绑定门店活动序列和当前人员资料/安全修订，根/筛选分页另绑定，不混页。

`POST /api/screening-projects[/:root]` 明确`record|withdraw`、所见修订/活动来源/人员来源和依据。读取正文后重核当前身份/门店/安全修订、强制改密，事务内再次检查会话和责任人。人员来源在缓存重放前核对，旧失效责任不能通过旧成功响应绕过；业务版本、审计和幂等结果整体提交或回滚。

前端冲突保留所有输入及责任选择，明确重读当前来源；原选责任失效仍展示“当前不可用”，不能静默换人。登记/重读编辑前也核对迟到来源，角色失效清空编辑/原详情/列表，退出清空。新记录和原版历史共用桌面手机页面；撤回展示原来源仍在历史，不把旧记录当作当前授权。
